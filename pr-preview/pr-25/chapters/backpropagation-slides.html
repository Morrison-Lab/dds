Brian Hutchinson’s CSCI 481/581 sets the order of topics in these notes, which follow it with his permission; this page covers the lecture on computing gradients in his module on machine learning fundamentals. The exercises are new. Recording a computation and running it backward follow Deep Learning, Section 6.5 [1].

1 Welcome

1.1 Plan for this lecture

Automatic differentiation gave the derivative of a loss without anyone writing it down. This lecture opens it up for the MLP on the digits:

  1. how PyTorch records the operations that compute a loss;
  2. how the chain rule, applied to those operations from the loss back to the input, gives the gradient with respect to every parameter at once, and how to compute it by hand and match PyTorch;
  3. why that costs only a few times as much as computing the loss once;
  4. why the gradient can shrink layer by layer in a deep network.

lds’s chapter on the same algorithm derives it for a general network with one hidden layer, and runs more experiments on depth.

2 Recording a computation

2.1 What the loss is made of

Exercise 1 (From an image to its loss)

Exercise 1 (From an image to its loss) List, in order, the operations that take one image \(\vx\) with true digit \(y\) to the MLP’s cross-entropy loss.

Solution 1

Solution 1. Write \(\matr{W}_1, \vecf{b}_1\) for the first layer’s parameters and \(\matr{W}_2, \vecf{b}_2\) for the second’s.

  1. \(\vz_1 = \matr{W}_1 \vx + \vecf{b}_1\), an affine function of the pixels;
  2. \(\vhidval = \operatorname{ReLU}(\vz_1)\), entry by entry;
  3. \(\vz_2 = \matr{W}_2 \vhidval + \vecf{b}_2\), the logits;
  4. \(\loss = -\log \operatorname{softmax}(\vz_2)_y\), the cross-entropy loss, where softmax is the softmax function.

Each step uses only the input and the results of earlier steps.

Definition 1 (Computational graph)

Definition 1 (Computational graph) A computational graph of a calculation has one node for each variable, whether an input, a parameter or an intermediate result, and an arrow from each node to every node computed from it [1, Sec. 6.5.1]. It has no cycles: following the arrows never returns to a node.

For the first training image, PyTorch’s computational graph holds the four steps of Solution 1, read from the loss back to the input. Each grad_fn names the operation that made a tensor:

  • NllLossBackward0 and LogSoftmaxBackward0 are step 4, which nn.CrossEntropyLoss computes as a log softmax followed by picking out entry \(y\);
  • AddmmBackward0 (“add matrix multiply”) is each affine step, 3 and then 1;
  • ReluBackward0 is step 2;
  • TBackward0 is the transpose of \(\matr{W}_1\) in x @ weight.T.

The chain stops at the transpose, since the image itself was not made with requires_grad=True.

3 The backward pass

3.1 The gradient at the logits

Exercise 2 (The gradient at the logits)

Exercise 2 (The gradient at the logits) Find the derivative of the cross-entropy loss \(\loss = -\log \operatorname{softmax}(\vz)_y\), where softmax is the softmax function, with respect to each logit \(z_m\), for \(m = 1, \dots, C\), where \(C\) is the number of classes.

Hint

Start from the log softmax theorem.

Solution 2

Solution 2. By the log softmax theorem, \(\loss = \operatorname{LSE}(\vz) - z_y\), where \(\operatorname{LSE}\) is log-sum-exp.

\[ \begin{aligned} \derivf{\operatorname{LSE}(\vz)}{z_m} &= \derivf{}{z_m} \log \sumto{k}{C} \e{z_k} && \text{(definition of $\operatorname{LSE}$)} \\ &= \frac{1}{\sumto{k}{C} \e{z_k}} \derivf{}{z_m} \sumto{k}{C} \e{z_k} && \text{(chain rule for $\log$)} \\ &= \frac{1}{\sumto{k}{C} \e{z_k}} \derivf{}{z_m} \e{z_m} && \text{(only term $k = m$ depends on $z_m$)} \\ &= \frac{\e{z_m}}{\sumto{k}{C} \e{z_k}} && \text{(derivative of the exponential)} \\ &= \operatorname{softmax}(\vz)_m && \text{(definition of softmax)} \end{aligned} \]

The second term, \(z_y\), has derivative 1 with respect to \(z_y\) and 0 with respect to every other logit. So

\[ \derivf{\loss}{z_m} = \operatorname{softmax}(\vz)_m - \indicf{m = y}. \]

Theorem 1 (Gradient of the cross-entropy loss at the logits)

Theorem 1 (Gradient of the cross-entropy loss at the logits) For logits \(\vz \in \reals^C\) and true class \(y\), the cross-entropy loss \(\loss = -\log \operatorname{softmax}(\vz)_y\), where softmax is the softmax function, has gradient

\[ \gradwrt{\vz} \loss = \operatorname{softmax}(\vz) - \ve_y, \]

where \(\ve_y\) has 1 in entry \(y\) and 0 in every other entry.

Proof

Proof. By Solution 2.

3.2 Through a linear layer

Exercise 3 (Gradient for a layer’s weight matrix)

Exercise 3 (Gradient for a layer’s weight matrix) A layer computes \(\vz = \matr{W} \vhidval + \vecf{b}\), and the gradient \(\vbackerr = \gradwrt{\vz} \loss\) of the loss with respect to its output is known. What is the gradient of \(\loss\) with respect to \(\matr{W}\)?

Solution 3

Solution 3. Entry \(j\) of the output is \(z_j = \sum_k W_{jk} h_k + b_j\), so \(W_{jk}\) affects \(\loss\) only through \(z_j\).

\[ \begin{aligned} \derivf{\loss}{W_{jk}} &= \derivf{\loss}{z_j} \derivf{z_j}{W_{jk}} && \text{(chain rule through $z_j$)} \\ &= \backerr_j h_k && \text{(since $\derivf{z_j}{W_{jk}} = h_k$)} \end{aligned} \]

As a matrix,

\[ \gradwrt{\matr{W}} \loss = \oprod{\vbackerr}{\vhidval}, \]

an \(m \times n\) outer product for a layer with \(n\) inputs and \(m\) outputs, with the same shape as \(\matr{W}\).

Exercise 4 (Gradient for a layer’s bias)

Exercise 4 (Gradient for a layer’s bias) For the layer of Exercise 3, what is the gradient of \(\loss\) with respect to \(\vecf{b}\)?

Solution 4

Solution 4. Bias \(b_j\) affects \(\loss\) only through \(z_j\), and \(\derivf{z_j}{b_j} = 1\), so \(\derivf{\loss}{b_j} = \backerr_j \cdot 1 = \backerr_j\), and

\[ \gradwrt{\vecf{b}} \loss = \vbackerr. \]

Exercise 5 (The gradient passed back)

Exercise 5 (The gradient passed back) For the layer of Exercise 3, find the gradient of \(\loss\) with respect to the layer’s input \(\vhidval\).

Solution 5

Solution 5. Input \(h_k\) affects every output \(z_j\), so the chain rule adds up a term for each:

\[ \begin{aligned} \derivf{\loss}{h_k} &= \sum_j \derivf{\loss}{z_j} \derivf{z_j}{h_k} && \text{(chain rule through every $z_j$)} \\ &= \sum_j \backerr_j W_{jk} && \text{(since $\derivf{z_j}{h_k} = W_{jk}$)} \\ &= \paren{\tp{\matr{W}} \vbackerr}_k && \text{(entry $k$ of a matrix-vector product)} \end{aligned} \]

So \(\gradwrt{\vhidval} \loss = \tp{\matr{W}} \vbackerr\): the gradient travels back through the layer by the transpose of its weight matrix.

3.3 Through the ReLU

Exercise 6 (Back through the ReLU)

Exercise 6 (Back through the ReLU) The hidden layer is \(\vhidval = \operatorname{ReLU}(\vz_1)\), entry by entry, and \(\gradwrt{\vhidval} \loss\) is known. Find \(\gradwrt{\vz_1} \loss\).

Solution 6

Solution 6. Entry \(h_k = \maxf{0, z_{1k}}\) depends only on \(z_{1k}\), with derivative 1 where \(z_{1k} > 0\) and 0 where \(z_{1k} < 0\); at \(z_{1k} = 0\) PyTorch, and these notes, take it to be 0, as in the slopes of the activation functions. So

\[ \derivf{\loss}{z_{1k}} = \derivf{\loss}{h_k} \, \indicf{z_{1k} > 0}: \]

the gradient passes through each unit that was positive and stops at each unit that was 0.

3.4 The whole backward pass

Exercise 7 (The backward pass by hand)

Exercise 7 (The backward pass by hand) Computed by hand from Theorem 1, Solution 3, Solution 4, Solution 5 and Solution 6, without .backward(), how closely does the gradient of the MLP’s mean loss over the training set with respect to \(\matr{W}_1\), \(\vecf{b}_1\), \(\matr{W}_2\) and \(\vecf{b}_2\) match the one loss.backward() gives?

Solution 7

Solution 7.

Show code
first, second = mlp[0], mlp[2]

# Forward, keeping every intermediate result.
z1 = x_train @ first.weight.T + first.bias
h = torch.relu(z1)
z2 = h @ second.weight.T + second.bias
loss = loss_fn(z2, y_train)

mlp.zero_grad()
loss.backward()

with torch.no_grad():
    # Backward, from the loss to the first layer, one row per image.
    g2 = (torch.softmax(z2, dim=1) - nn.functional.one_hot(y_train, 10)) / n_train
    grad_W2 = g2.T @ h
    grad_b2 = g2.sum(dim=0)
    grad_h = g2 @ second.weight
    grad_z1 = grad_h * (z1 > 0)
    grad_W1 = grad_z1.T @ x_train
    grad_b1 = grad_z1.sum(dim=0)

pairs = [(grad_W1, first.weight), (grad_b1, first.bias),
         (grad_W2, second.weight), (grad_b2, second.bias)]
backward_gap = max((mine - p.grad).abs().max().item() for mine, p in pairs)
print(backward_gap)
7.450580596923828e-09

The four gradients match autograd’s to within 7.5e-09. The code runs the steps of Solution 1 forward, then their derivatives in reverse:

  • g2 is \(\gradwrt{\vz_2} \loss\) from Theorem 1, for every image at once, divided by 1200 because the loss is the mean over that many images;
  • grad_W2 and grad_b2 are Solution 3 and Solution 4, with the outer products of the images added up by one matrix product;
  • grad_h is Solution 5, written for rows instead of columns;
  • grad_z1 is Solution 6;
  • grad_W1 and grad_b1 are Solution 3 and Solution 4 again, for the first layer.

The backward steps reuse z1 and h from the forward pass.

Definition 2 (Backpropagation (backprop))

Definition 2 (Backpropagation (backprop)) Backpropagation, or backprop, computes the gradient of a scalar, such as a loss, with respect to every node of a computational graph: it visits the nodes in the reverse of the order the forward computation made them, and at each node applies the chain rule, combining the gradient with respect to the node’s output with the derivative of the node’s own operation [1, Sec. 6.5], [3].

Backpropagation is reverse-mode automatic differentiation applied to a network’s loss, and PyTorch’s .backward() runs it. Some sources use “backpropagation” for the whole training algorithm, including the parameter update; these notes use it only for computing the gradient.

Example 3 (Backpropagation through the MLP)

Example 3 (Backpropagation through the MLP) Solution 7 is backpropagation through the four steps of Solution 1. It visits them in reverse order: the loss gives the gradient at the logits g2; the second affine step gives the gradients of \(\matr{W}_2\), \(\vecf{b}_2\) and the hidden layer; the ReLU gives the gradient at \(\vz_1\); and the first affine step gives the gradients of \(\matr{W}_1\) and \(\vecf{b}_1\).

4 Cost

4.1 Backpropagation against finite differences

Exercise 8 (The cost of finite differences)

Exercise 8 (The cost of finite differences) A finite difference, \(\paren{\loss(\theta_i + \smallconst) - \loss(\theta_i)} / \smallconst\) for a small \(\smallconst\), estimates the derivative of the MLP’s mean training loss \(\loss\) with respect to one parameter \(\theta_i\), with every other parameter held fixed. How many evaluations of the loss does that take to estimate the gradient with respect to \(P\) parameters?

Solution 8

Solution 8. \(P + 1\): one at the current parameters, and one more for each parameter nudged. Backpropagation gets all \(P\) derivatives from one forward pass and one backward pass, and each backward step costs a small multiple of its forward step: a matrix product forward becomes two matrix products backward, as in Solution 3 and Solution 5, so the two passes together cost about three forward passes.

Show code
def mean_loss():
    return loss_fn(mlp(x_train), y_train)

start = time.perf_counter()
for repeat in range(20):
    mlp.zero_grad()
    mean_loss().backward()
backprop_seconds = (time.perf_counter() - start) / 20

start = time.perf_counter()
with torch.no_grad():
    base = mean_loss()
    w = second.weight
    estimate = torch.zeros_like(w)
    for j in range(w.shape[0]):
        for k in range(w.shape[1]):
            w[j, k] += 1e-3
            estimate[j, k] = (mean_loss() - base) / 1e-3
            w[j, k] -= 1e-3
difference_seconds = time.perf_counter() - start
fd_gap = (estimate - second.weight.grad).abs().max().item()
print(backprop_seconds, difference_seconds, fd_gap)
0.005830402300000514 0.15436204900004213 0.00044121919199824333

One forward and backward pass over the training set took 5.83 milliseconds, for every parameter of the MLP. Finite differences for only the 320 entries of \(\matr{W}_2\) took 154 milliseconds, 26 times as long, and agree with backpropagation only to within 0.00044, since a finite difference is an approximation. Timings vary from run to run; the ratio grows with the number of parameters.

Remark 1 (What backpropagation stores)

Remark 1 (What backpropagation stores). The backward steps of Solution 7 reuse z1 and h from the forward pass, so PyTorch keeps every intermediate result that a later backward step needs until .backward() has run. That memory grows with the number of layers and with the batch size, and it is often what limits the batch size on a GPU. Code run inside torch.no_grad(), such as computing test accuracy, records nothing and keeps nothing.

5 Gradients in deep networks

5.1 Gradient sizes layer by layer

Exercise 9 (Gradients in a deep network)

Exercise 9 (Gradients in a deep network) Take two MLPs for the digits with 10 hidden layers of 32 units each, one with the logistic function as its activation function and one with the ReLU. At their starting weights, how does the size of the gradient of the mean training loss with respect to each layer’s weight matrix change from the last layer to the first?

Solution 9

Solution 9.

Show code
def deep_mlp(activation, n_hidden=10, width=32):
    _ = torch.manual_seed(0)
    layers, n_in = [], 64
    for layer in range(n_hidden):
        layers += [nn.Linear(n_in, width), activation()]
        n_in = width
    layers.append(nn.Linear(width, 10))
    return nn.Sequential(*layers)


grad_norms = {}
for name, activation in [("logistic", nn.Sigmoid), ("ReLU", nn.ReLU)]:
    net = deep_mlp(activation)
    loss_fn(net(x_train), y_train).backward()
    grad_norms[name] = [m.weight.grad.norm().item() for m in net if isinstance(m, nn.Linear)]

fig, ax = plt.subplots(figsize=(6, 3.5), layout="constrained")
for name, norms in grad_norms.items():
    ax.semilogy(range(1, len(norms) + 1), norms, marker="o", label=name);
ax.set_xlabel("layer (1 = first)");
ax.set_ylabel("size of weight gradient");
ax.legend();
plt.show()
Show code
shrink = {name: norms[-1] / norms[0] for name, norms in grad_norms.items()}
print(shrink)
{'logistic': 129510900.18186893, 'ReLU': 251.30350519888285}

The size of a matrix here is the square root of the sum of its squared entries. In both networks the weight gradient is largest at the last layer. With the logistic function, the weight gradient shrinks at every layer going back, and the last layer’s weight gradient is about \(10^{8}\) times the first layer’s. With the ReLU, the weight gradient shrinks over the last few layers and then levels off, and the last layer’s is 251 times the first layer’s. A training step with one learning rate would move the logistic network’s first layers almost not at all.

5.2 Why they shrink

Exercise 10 (Why the gradient shrinks)

Exercise 10 (Why the gradient shrinks) In a deep MLP, hidden layer \(\layeridx\) is \(\vhidval_{\layeridx} = g\paren{\vz_{\layeridx}}\) with \(\vz_{\layeridx} = \matr{W}_{\layeridx} \vhidval_{\layeridx - 1} + \vecf{b}_{\layeridx}\). Why does the gradient shrink from layer to layer, going back, when \(g\) is the logistic function?

Solution 10

Solution 10. Applying Solution 6’s reasoning to \(g\), then Solution 5, takes the gradient back one layer:

\[ \gradwrt{\vhidval_{\layeridx - 1}} \loss = \tp{\matr{W}_{\layeridx}} \vbackerr_{\layeridx}, \qquad \vbackerr_{\layeridx} = \gradwrt{\vz_{\layeridx}} \loss = g'(\vz_{\layeridx}) \odot \gradwrt{\vhidval_{\layeridx}} \loss, \]

where \(\odot\) multiplies entry by entry. Each layer back multiplies the gradient by the slopes \(g'(\vz_{\layeridx})\) and by \(\tp{\matr{W}_{\layeridx}}\). The logistic function’s slope is at most \(\frac{1}{4}\) (lds’s bound on it), and less where units saturate, so unless the weights are large, every layer shrinks the gradient by a factor less than 1, and 10 layers multiply 10 such factors. The ReLU’s slope has no \(\frac{1}{4}\) bound: it is 1 at each unit that is positive and 0 at each unit that is not. In the ReLU network of Solution 9, the gradient going back still shrinks, both because the weights PyTorch starts with are small and because the units at 0 pass none of it back.

The weight gradient of layer \(\layeridx\) is \(\oprod{\vbackerr_{\layeridx}}{\vhidval_{\layeridx - 1}}\), by Solution 3, so its size depends on the layer’s input \(\vhidval_{\layeridx - 1}\) as well as on the gradient \(\vbackerr_{\layeridx}\) at its output. In the ReLU network the layer inputs grow toward the first layers, which is why its weight gradients level off there while the gradients \(\vbackerr_{\layeridx}\) keep shrinking.

Definition 3 (Vanishing gradient)

Definition 3 (Vanishing gradient) A network has a vanishing gradient when the gradient of its loss with respect to the parameters of its early layers is many orders of magnitude smaller than with respect to those of its later layers, because backpropagation multiplies it by a factor smaller than 1 at each layer [1, Sec. 8.2.5], [4]. The early layers then learn far more slowly than the later ones, or not at all.

The opposite, a gradient that grows layer by layer, is an exploding gradient.

Example 4 (The deep logistic network)

Example 4 (The deep logistic network) The 10-hidden-layer logistic network of Solution 9 has a vanishing gradient: its first layer’s weight gradient is about \(10^{-8}\) times its last layer’s.

Remark 2 (What keeps gradients from vanishing)

Remark 2 (What keeps gradients from vanishing). The ReLU removes the \(\frac{1}{4}\) bound on each layer’s slopes. Other remedies are starting the weights at a scale that keeps the gradient’s size steady from layer to layer, such as He initialization or Glorot initialization, normalizing each layer’s values, and residual connections, which give the gradient a path around each layer. lds’s experiment on depth measures the same effect.
