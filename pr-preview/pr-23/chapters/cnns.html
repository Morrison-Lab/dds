1 Welcome

1.1 Plan for this lecture

The DATA 471 notes built convolutional layers by hand, with padding, stride, pooling and channels. This lecture puts them to work in PyTorch:

  1. the shapes that nn.Conv2d takes and returns;
  2. how far across the image one output of a stack of layers can see;
  3. what happens to a convolutional network, and to an MLP, when a digit moves by one pixel;
  4. a short history of the architectures built from these layers;
  5. reusing a network trained on one task to start another.

1.2 The digits as images

Show code
import copy

import numpy as np
import pandas as pd
import torch
from torch import nn

_ = torch.manual_seed(481)
digits = pd.read_csv("data/optdigits-test.csv", header=None)
pixels = torch.tensor(digits.iloc[:, :64].to_numpy(), dtype=torch.float32) / 16
x = pixels.reshape(-1, 1, 8, 8)
y = torch.tensor(digits[64].to_numpy())
n_train = 1200
order = torch.randperm(len(x))
x_train, y_train = x[order[:n_train]], y[order[:n_train]]
x_test, y_test = x[order[n_train:]], y[order[n_train:]]
loss_fn = nn.CrossEntropyLoss()


def train(net, xs, ys, n_epochs=10, lr=0.05, batch_size=32, seed=0, params=None):
    # Minibatch SGD with momentum 0.9.
    # `params` picks the tensors to update; by default, all of them.
    if params is None:
        params = net.parameters()
    optimizer = torch.optim.SGD(params, lr=lr, momentum=0.9)
    generator = torch.Generator().manual_seed(seed)
    for epoch in range(n_epochs):
        net.train()
        shuffled = torch.randperm(len(xs), generator=generator)
        for start in range(0, len(xs), batch_size):
            batch = shuffled[start:start + batch_size]
            optimizer.zero_grad()
            loss_fn(net(xs[batch]), ys[batch]).backward()
            optimizer.step()
    return net


def accuracy(net, xs, ys):
    # Fraction of the images in `xs` that `net` classifies correctly.
    net.eval()
    with torch.no_grad():
        return (net(xs).argmax(dim=1) == ys).float().mean().item()


def make_cnn(n_classes=10, seed=1):
    # Two 3-by-3 convolutional layers, 2-by-2 max pooling, then a linear layer.
    torch.manual_seed(seed)
    return nn.Sequential(
        nn.Conv2d(1, 8, 3, padding=1), nn.ReLU(),
        nn.Conv2d(8, 16, 3, padding=1), nn.ReLU(),
        nn.MaxPool2d(2),
        nn.Flatten(),
        nn.Linear(16 * 4 * 4, n_classes),
    )


def make_mlp(seed=1):
    # One hidden layer of 64 ReLU units, on the 64 pixels.
    torch.manual_seed(seed)
    return nn.Sequential(nn.Flatten(), nn.Linear(64, 64), nn.ReLU(), nn.Linear(64, 10))


def n_params(net):
    return sum(p.numel() for p in net.parameters())


print(x_train.shape, x_test.shape)
torch.Size([1200, 1, 8, 8]) torch.Size([597, 1, 8, 8])

The exercises use the UCI optical digits [1], split as in the feedforward networks chapter, with 1,200 training images, but keep each image as a grid: a tensor of shape \(1 \times 8 \times 8\), for one channel of 8 rows and 8 columns. train() runs minibatch stochastic gradient descent with momentum 0.9, learning rate 0.05 and batch size 32. make_cnn() builds a small convolutional network, with 3,818 parameters. make_mlp() builds an MLP with one hidden layer of 64 ReLU units, with 4,810 parameters.

Solution 1.

conv = nn.Conv2d(1, 8, 3, padding=1)

conv_out has shape \(32 \times 8 \times 8 \times 8\): 32 images, each with 8 channels of 8 rows and 8 columns. At \((4, 4)\), the second layer’s output reads a \(3 \times 3\) block of the first layer’s output, rows and columns 3 to 5. Each of those 9 outputs of the first layer reads its own \(3 \times 3\) block of the input, so together they read rows and columns 2 to 6. The gradient of that one output with respect to the input, printed as 1 where it is not 0, is not 0 on a block of 5 rows by 5 columns. Every other pixel leaves the output unchanged.

DefDefinition 1 (Receptive field)

Definition 1 (Receptive field) The receptive field of a unit in a convolutional network is the set of input pixels whose values can change the unit’s value [3, Sec. 9.2].

ExmExample 1 (Receptive fields in make_cnn())

Example 1 (Receptive fields in make_cnn())  

Show code
def field_size(layers, row, col):
    # Rows and columns of the input that reach any channel of `layers` at (row, col),
    # over 64 training images; one image can miss a pixel through a ReLU that is 0.
    images = x_train[:64].clone().requires_grad_(True)
    layers(images)[:, :, row, col].sum().backward()
    reaches = (images.grad != 0).any(dim=0)[0]
    return reaches.any(dim=1).sum().item(), reaches.any(dim=0).sum().item()


conv_net = make_cnn()
before_pool = field_size(conv_net[:4], row=4, col=4)
after_pool = field_size(conv_net[:5], row=2, col=2)
print(before_pool, after_pool)
(5, 5) (6, 6)

make_cnn() stacks two \(3 \times 3\) convolutional layers, each followed by a ReLU, then \(2 \times 2\) max pooling. A unit of the second convolutional layer has a receptive field of 5 by 5 pixels. A unit after the pooling layer takes the largest of a \(2 \times 2\) block of those units. Its receptive field is 6 by 6 pixels.

RemarkRemark 1 (How fast a receptive field grows)

Remark 1 (How fast a receptive field grows). A \(k \times k\) convolutional layer with stride 1 makes each side of the receptive field \(k - 1\) pixels longer. So \(L\) such layers of \(3 \times 3\) filters give a receptive field of \((2L + 1) \times (2L + 1)\) pixels, away from the edges of the image. Solution 2 found \(L = 2\) layers and a \(5 \times 5\) block. Pooling and stride make the receptive field grow faster, since each step of a later layer then moves farther across the input [3, Sec. 9.2].

3.2 Small filters

ExrExercise 3 (Two small filters or one large one)

Exercise 3 (Two small filters or one large one) Two stacked \(3 \times 3\) convolutional layers and one \(5 \times 5\) layer have the same receptive field. Suppose every layer has \(C\) input channels and \(C\) output channels. Which of the two designs has fewer weights, not counting biases?

SolutionSolution 3

Solution 3. A \(k \times k\) layer from \(C\) channels to \(C\) channels has one \(k \times k \times C\) filter per output channel, so \(k^2 C^2\) weights. Two \(3 \times 3\) layers have \(2 \times 9 C^2 = 18 C^2\) weights, and one \(5 \times 5\) layer has \(25 C^2\). So the two small layers have fewer weights, 72% as many. They can also apply an activation function between them, as make_cnn() does, so they can compute functions of the patch that one layer cannot. The VGG networks are built from stacks of \(3 \times 3\) layers for these two reasons [4, Sec. 2.3].

Show code
channels = 16
small = nn.Sequential(nn.Conv2d(channels, channels, 3), nn.Conv2d(channels, channels, 3))
large = nn.Conv2d(channels, channels, 5)
small_weights = sum(layer.weight.numel() for layer in small)
large_weights = large.weight.numel()
print(small_weights, large_weights)
4608 6400

For \(C = 16\), PyTorch’s layers have 4,608 and 6,400 weights.

4 Shifted digits

4.1 Shifting the input of a convolution

ExrExercise 4 (Moving the input of a convolution)

Exercise 4 (Moving the input of a convolution) shift_right() below moves each image one pixel to the right, filling the left column with 0. Apply a convolutional layer to a test digit and to its shifted copy. How does the output for the shifted copy compare with the output for the original?

Show code
def shift_right(images):
    # Move each image in a batch one pixel right; the left column becomes 0.
    moved = torch.zeros_like(images)
    moved[..., 1:] = images[..., :-1]
    return moved


print(x_test[0, 0, :3], shift_right(x_test[:1])[0, 0, :3], sep="\n")
tensor([[0.0000, 0.0000, 0.4375, 0.8125, 0.1250, 0.0000, 0.0000, 0.0000],

        [0.0000, 0.7500, 0.4375, 0.0000, 1.0000, 0.2500, 0.0000, 0.0000]])
tensor([[0.0000, 0.0000, 0.0000, 0.4375, 0.8125, 0.1250, 0.0000, 0.0000],

Solution 4.

Show code
digit = x_test[:1]
with torch.no_grad():
    out_of_shifted = conv(shift_right(digit))
    shifted_out = shift_right(conv(digit))
gap = (out_of_shifted - shifted_out).abs()
gap_inside = gap[..., 1:].max().item()
gap_first_col = gap[..., 0].max().item()
last_col_blank = digit[..., 7].abs().max().item() == 0
print(gap_inside, gap_first_col)
0.0 0.33131906390190125

conv(shift_right(digit)) is conv(digit) shifted one pixel right. Each output pixel is the same filter applied to the patch around it, so moving every patch moves every output. In columns 1 to 7 of every channel of conv, the two agree exactly. In column 0 they differ by up to 0.33. There shift_right() fills the shifted output with 0, while the layer applies its filter and bias to the new blank column. Column 7 agrees only because this digit’s last column is blank.

DefDefinition 2 (Translation equivariance)

Definition 2 (Translation equivariance) A function \(f\) from images to images is translation equivariant when shifting its input shifts its output by the same amount: \(f(\operatorname{shift}(x)) = \operatorname{shift}(f(x))\) for every image \(x\) and every shift [3, Sec. 9.2]. A convolutional layer with stride 1 is translation equivariant, up to what happens at the edges of the image.

ExmExample 2 (ReLU and max pooling)

Example 2 (ReLU and max pooling)  

Show code
relu, pool = nn.ReLU(), nn.MaxPool2d(2)
with torch.no_grad():
    maps = conv(x_test[:1])
    relu_gap = (relu(shift_right(maps)) - shift_right(relu(maps))).abs().max().item()
    pooled_shift = pool(shift_right(maps))
    pooled = pool(maps)
pool_shape = list(pooled.shape[2:])
pool_gap = (pooled_shift - pooled).abs().max().item()
pool_shift_gap = (pooled_shift - shift_right(pooled)).abs().max().item()
print(relu_gap, pool_shape, pool_gap, pool_shift_gap)
0.0 [4, 4] 0.4551493525505066 0.5029639601707458

A ReLU acts on each pixel separately. So a ReLU is translation equivariant with no edge effect. On the feature maps of conv for a test digit, relu(shift_right(maps)) and shift_right(relu(maps)) agree exactly. A \(2 \times 2\) max pooling layer is not translation equivariant. Its output is 4 by 4. A shift of one input pixel is half an output pixel, and no whole-pixel shift of the pooled maps matches a half-pixel shift. The pooled maps of the shifted input differ by up to 0.46 from those of the unshifted input, and by up to 0.50 from those maps shifted one pixel right.

The MLP loses more: 51.8 percentage points, against 17.9 for the convolutional network. The MLP has a separate weight for each pixel. A stroke that moves to a new column meets weights trained on other strokes. The convolutional layers are translation equivariant. They find the same strokes one column over. The pooling layer is not translation equivariant (Example 2). The last linear layer has a separate weight for each pooled position, as the MLP has for each pixel.

5 Architectures

5.1 Four landmarks

RemarkRemark 2 (Some convolutional networks that changed the field)

Remark 2 (Some convolutional networks that changed the field).

  • LeNet-5 read handwritten digits with three convolutional layers, the first two each followed by subsampling, then one fully connected layer [5, Sec. II.B].
  • AlexNet won the 2012 ImageNet competition with 5 convolutional layers, ReLU activations, dropout and training on GPUs [6, Sec. 3].
  • VGG networks stacked \(3 \times 3\) convolutional layers, up to 19 weight layers deep [4, Sec. 2.3], for the reasons in Solution 3.
  • ResNets added residual connections around pairs or triples of convolutional layers, and trained networks of more than 100 layers [7]. The normalization chapter used residual connections around single fully connected layers.

6.2 Reusing layers

ExrExercise 7 (Reusing the convolutional layers)

Exercise 7 (Reusing the convolutional layers)  

Show code
is_low = y_train < 5
n_low = int(is_low.sum())
low_net = train(make_cnn(n_classes=5), x_train[is_low], y_train[is_low])
low_test = y_test < 5
low_acc = accuracy(low_net, x_test[low_test], y_test[low_test])


def new_head(train_all, seed=3):
    # Copy low_net with a new last layer; return it and the parameters to train.
    net = copy.deepcopy(low_net)
    torch.manual_seed(seed)
    net[-1] = nn.Linear(16 * 4 * 4, 5)
    if train_all:
        return net, net.parameters()
    return net, net[-1].parameters()


print(n_low, low_acc)
598 0.9933993220329285

The training set has 598 labelled images of the digits 0 to 4. low_net is make_cnn(n_classes=5) trained on them. new_head() copies low_net, replaces its last linear layer with a new one for the digits 5 to 9, and returns the copy with the parameters to train. With train_all=False, those are only the new layer’s. The convolutional layers keep the weights they learned on the digits 0 to 4. Trained this way on the 20 images of each draw, is the network more accurate than the networks of Solution 6?

DefDefinition 3 (Transfer learning)

Definition 3 (Transfer learning) Transfer learning uses what a network learned on one task to start learning another task, usually one with far fewer labelled examples [3, Sec. 15.2]. One common form keeps the early layers of a network trained on the first task, and trains a new last layer for the second. Networks trained on ImageNet are often reused this way: their first layers find edge-like patterns that are useful for many kinds of images [8].

ExmExample 3 (Fixing layers with requires_grad)

Example 3 (Fixing layers with requires_grad)  

Show code
reused, _ = new_head(train_all=False)
for param in reused[:-1].parameters():
    _ = param.requires_grad_(False)
n_trainable = sum(p.numel() for p in reused.parameters() if p.requires_grad)
print(n_trainable, n_params(reused))
1285 2533

Solution 7 is transfer learning from the digits 0 to 4 to the digits 5 to 9. It kept the convolutional layers fixed by handing the optimizer only the new layer’s parameters. Another common way marks the reused parameters with requires_grad_(False). Then backpropagation computes no gradients for them. Of the 2,533 parameters of the copy, 1,285 still require gradients.

DefDefinition 4 (Fine-tuning)

Definition 4 (Fine-tuning) Fine-tuning is transfer learning that trains every layer on the second task, starting from the weights learned on the first, rather than keeping the early layers fixed [8].

    ],
    lr=0.05,
    momentum=0.9,
)
group_lrs = [group["lr"] for group in optimizer.param_groups]
print(group_lrs)
[0.005, 0.05]

Solution 8 ran fine-tuning with one learning rate for every layer. A PyTorch optimizer also takes a list of groups of parameters, each with its own options [9]. optimizer here would move the reused convolutional layers with learning rate 0.005 and the new last layer with learning rate 0.05.
