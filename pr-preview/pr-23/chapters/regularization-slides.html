Brian Hutchinson’s CSCI 481/581 sets the order of topics in these notes, which follow it with his permission; this page covers the regularization part of his module on optimization and regularization. The exercises are new. This page’s methods follow Deep Learning, Chapter 7 [1].

1 Welcome

1.1 Plan for this lecture

The optimization chapter made training faster. This lecture is about what training finds: a network with many parameters can fit its training set far better than new images, and regularization trades some of that fit for better predictions. It covers

  1. watching a validation set during training, and stopping at the best point;
  2. weight decay in PyTorch’s optimizers;
  3. randomly switching off units during training;
  4. training on transformed copies of the training images.

1.2 The digits and the network

Show code
import copy

import numpy as np
import pandas as pd
import torch
from torch import nn
import matplotlib.pyplot as plt

_ = torch.manual_seed(481)
digits = pd.read_csv("data/optdigits-test.csv", header=None)
x = torch.tensor(digits.iloc[:, :64].to_numpy(), dtype=torch.float32) / 16
y = torch.tensor(digits[64].to_numpy())
n_train, n_val = 150, 400
order = torch.randperm(len(x))
train_idx = order[:n_train]
val_idx = order[n_train:n_train + n_val]
test_idx = order[n_train + n_val:]
x_train, y_train = x[train_idx], y[train_idx]
x_val, y_val = x[val_idx], y[val_idx]
x_test, y_test = x[test_idx], y[test_idx]
n_test = len(x_test)
loss_fn = nn.CrossEntropyLoss()


def make_net(seed=1):
    # 64 pixels, a hidden layer of 256 ReLU units, then 10 logits.
    torch.manual_seed(seed)
    return nn.Sequential(nn.Linear(64, 256), nn.ReLU(), nn.Linear(256, 10))


def accuracy(net, inputs, targets):
    # Share of `inputs` whose largest logit is the true digit.
    net.eval()
    with torch.no_grad():
        return (net(inputs).argmax(dim=1) == targets).float().mean().item()


def fit(net, n_epochs=300, weight_decay=0.0, transform=None, seed=0):
    # Full-batch AdamW on the training images.
    # Records both losses after every epoch, and keeps the parameters
    # from the epoch with the lowest validation loss.
    optimizer = torch.optim.AdamW(net.parameters(), lr=0.01, weight_decay=weight_decay)
    generator = torch.Generator().manual_seed(seed)
    history, best_state, best_val = [], None, float("inf")
    for epoch in range(1, n_epochs + 1):
        net.train()
        inputs = x_train if transform is None else transform(x_train, generator)
        optimizer.zero_grad()
        loss_fn(net(inputs), y_train).backward()
        optimizer.step()
        net.eval()
        with torch.no_grad():
            train_loss = loss_fn(net(x_train), y_train).item()
            val_loss = loss_fn(net(x_val), y_val).item()
        history.append({"epoch": epoch, "train": train_loss, "val": val_loss})
        if val_loss < best_val:
            best_val, best_state = val_loss, copy.deepcopy(net.state_dict())
    return pd.DataFrame(history), best_state


n_params = sum(p.numel() for p in make_net().parameters())
print(len(x_train), len(x_val), len(x_test), n_params)
150 400 1247 19210

The exercises use the 1,797 digits of data/optdigits-test.csv [2]. To make a network fit its training images too well, the training set here is small, 150 random images. Another 400 form a validation set, and the other 1,247 a test set. make_net() builds an MLP with one hidden layer of 256 ReLU units, which has 19,210 parameters. fit() trains it by full-batch AdamW, PyTorch’s variant of Adam with weight decay, with learning rate 0.01 and no weight decay unless asked. It records the training and validation losses after every epoch.

2.2 Stopping at the best epoch

Definition 1 (Early stopping)

Definition 1 (Early stopping) Early stopping records the validation loss after every epoch of training, and returns the parameters from the epoch with the lowest validation loss [1, Sec. 7.8].

fit() already does early stopping: it keeps the parameters of epoch 28 of Solution 1. On the 1247 test images, those parameters have loss 0.305, against 0.384 after all 300 epochs. The test accuracies are 92.4% and 92.3%. The accuracy moves much less than the loss, because the loss also measures how much probability the network gives the true digit, not only whether that digit gets the most. fit() runs all 300 epochs; an early-stopping loop can instead end training once the validation loss has not improved for a set number of epochs.

3 Weight decay

3.1 Weight decay in PyTorch

Remark 1 (Weight decay in PyTorch)

Remark 1 (Weight decay in PyTorch). lds defines weight decay for gradient descent, with decay coefficient \(\lambda_{\text{wd}}\). PyTorch’s optimizers take an argument weight_decay, and its meaning depends on the optimizer. torch.optim.SGD and torch.optim.Adam add \(\lambda_{\text{wd}} \theta\) to the gradient of each parameter \(\theta\) before they take their step, an L2 penalty [3], [4]. For plain gradient descent, adding \(\lambda_{\text{wd}} \theta\) shrinks every parameter by the same factor at each step, so the penalty is weight decay. Adam divides the added \(\lambda_{\text{wd}} \theta\) by its running scale of past gradients, so the penalty shrinks parameters with small past gradients more than parameters with large ones [5]. torch.optim.AdamW instead multiplies each parameter by \(1 - \learnrate \lambda_{\text{wd}}\) before Adam’s step [6], PyTorch’s form of the decoupled weight decay of Loshchilov and Hutter [5]. fit() uses AdamW. weight_decay applies to the biases too, unless the optimizer is given them as a separate group with weight_decay=0.

3.2 Choosing the weight decay

Solution 2.

def weight_norm(net):
    # Euclidean norm of all the weights, leaving out the biases.
    weights = [p.flatten() for name, p in net.named_parameters() if "weight" in name]
    return torch.cat(weights).norm().item()


decay_rows = []
for weight_decay in [0, 0.1, 1, 10]:
    decay_net = make_net()
    decay_history, _ = fit(decay_net, weight_decay=weight_decay)
    decay_rows.append({
        "weight_decay": weight_decay,
        "train_loss": decay_history["train"].iloc[-1],
        "val_loss": decay_history["val"].iloc[-1],
        "weight_norm": weight_norm(decay_net),
    })
decay_table = pd.DataFrame(decay_rows)
best_decay = decay_table.loc[decay_table["val_loss"].idxmin()]
print(decay_table.round(4))
   weight_decay  train_loss  val_loss  weight_norm

1           0.1      0.0007    0.3178      21.1014

weight_decay \(= 1\) ends with the lowest validation loss, 0.276, against 0.363 with no weight decay. Weight decay keeps the weights smaller: their norm after 300 epochs falls from 22.9 with no weight decay to 9.4 with weight_decay \(= 10\). At 10 its training loss is 0.216, against 1.5e-04 with no weight decay, so it fits its training images less closely.

4 Switching off units at random

4.1 Not relying on any one unit

Exercise 3 (Not relying on any one unit)

Exercise 3 (Not relying on any one unit) How could training stop a network from relying on any single unit of its hidden layer?

Solution 3

Solution 3. Switch off a random set of units at each training step. A unit that may be missing at any step cannot carry a prediction on its own, so each prediction has to rest on many units [7].

4.2 Definition

Definition 2 (Dropout)

Definition 2 (Dropout) Dropout with rate \(p\) sets each unit of a layer to 0 independently with probability \(p\) at each training step, and multiplies the units it keeps by \(1 / (1 - p)\). When the network makes predictions, dropout leaves the layer unchanged [1, Sec. 7.12], [7]. Srivastava et al. [7] write \(p\) for the probability of keeping a unit, and multiply the weights out of the layer at prediction time instead, which gives the same expected values; PyTorch’s nn.Dropout scales during training [8].

Example 2 (nn.Dropout in training and in evaluation)

Example 2 (nn.Dropout in training and in evaluation)  

Show code
dropout = nn.Dropout(p=0.5)
ones = torch.ones(8)
_ = torch.manual_seed(0)
_ = dropout.train()
print(dropout(ones))
tensor([0., 0., 2., 0., 0., 0., 2., 2.])
Show code
_ = dropout.eval()
print(dropout(ones))
tensor([1., 1., 1., 1., 1., 1., 1., 1.])

In training mode, nn.Dropout(p=0.5) sets each entry of a vector of 8 ones to 0 with probability \(\frac{1}{2}\), and multiplies the others by \(1 / (1 - \frac{1}{2}) = 2\). After .eval() it returns its input unchanged. net.train() and net.eval() switch every dropout layer of a network, which is why fit() and accuracy() call them.

4.3 Why scale the units that are kept?

Exercise 4 (Why scale the units that are kept?)

Exercise 4 (Why scale the units that are kept?) Why does dropout multiply the units it keeps by \(1 / (1 - p)\)?

Solution 4

Solution 4. So that each unit’s expected value during training equals its value at prediction time. A unit with value \(h\) becomes \(D = 0\) with probability \(p\), and \(D = h / (1 - p)\) with probability \(1 - p\), so its expected value is

\[ \E{D} = p \cdot 0 + (1 - p) \cdot \frac{h}{1 - p} = h. \]

The next layer then sees inputs of the same size on average in both modes.

Show code
_ = torch.manual_seed(0)
_ = dropout.train()
mean_kept = dropout(torch.ones(100_000)).mean().item()
print(mean_kept)
0.9985799789428711

Averaged over 100,000 ones, nn.Dropout(p=0.5) in training mode gives 0.999.

5 Transformed training images

5.1 More training images for free

Exercise 7 (More training images for free)

Exercise 7 (More training images for free) The training set has only 150 images. How could training see more images of digits without anyone labelling new ones?

Solution 7

Solution 7. Change the training images in ways that leave the digit the same, such as adding a little noise or moving the digit slightly, and train on the changed copies with the original labels [1, Sec. 7.4].

5.2 Definition

Definition 3 (Data augmentation)

Definition 3 (Data augmentation) Data augmentation trains on transformed copies of the training inputs, made by transformations that should not change the target [1, Sec. 7.4]. Usually a new random transformation is drawn for each input at each epoch.

Example 3 (Noise and shifts for the digits)

Example 3 (Noise and shifts for the digits)  

Show code
def add_noise(images, generator, sd=0.2):
    # Add independent normal noise with standard deviation `sd` to every pixel.
    return images + sd * torch.randn(images.shape, generator=generator)


def shift_images(images, rows, cols):
    # Move each 8-by-8 image by (rows, cols) pixels, filling the gap with 0.
    grid = images.reshape(-1, 8, 8)
    moved = torch.roll(grid, shifts=(rows, cols), dims=(1, 2))
    if rows > 0:
        moved[:, :rows, :] = 0
    if rows < 0:
        moved[:, rows:, :] = 0
    if cols > 0:
        moved[:, :, :cols] = 0
    if cols < 0:
        moved[:, :, cols:] = 0
    return moved.reshape(-1, 64)


example = x_train[:1]
noisy = add_noise(example, torch.Generator().manual_seed(0))
shifted = shift_images(example, 0, 1)
fig, axes = plt.subplots(1, 3, figsize=(6, 2.2), layout="constrained")
for ax, image, title in zip(axes, [example, noisy, shifted], ["original", "noise", "shifted"]):
    ax.imshow(image.reshape(8, 8), cmap="gray_r");
    ax.set_title(title);
    ax.axis("off");
plt.show()

The first training image is a 0. Adding normal noise with standard deviation 0.2 to every pixel leaves it recognizable, and so does moving it one pixel to the right. Both are candidate transformations for data augmentation on the digits.

5.4 Shifted digits

Exercise 9 (Training on shifted digits)

Exercise 9 (Training on shifted digits) Suppose instead each training image is moved at random by \(-1\), 0 or 1 pixels in each direction at every epoch. Is the lowest validation loss of make_net() then lower than without shifts?

Solution 9

Solution 9.

Show code
def random_shift(images, generator):
    # Move each image by its own random (rows, cols), each -1, 0 or 1.
    moves = torch.randint(-1, 2, (len(images), 2), generator=generator)
    out = images.clone()
    for rows in [-1, 0, 1]:
        for cols in [-1, 0, 1]:
            chosen = (moves[:, 0] == rows) & (moves[:, 1] == cols)
            out[chosen] = shift_images(images[chosen], rows, cols)
    return out


shift_net = make_net()
shift_history, _ = fit(shift_net, transform=random_shift)
shift_best_val = shift_history["val"].min()
val_acc_plain = accuracy(stopped_net, x_val, y_val)
val_acc_moved = accuracy(stopped_net, shift_images(x_val, 0, 1), y_val)
print(shift_best_val, best_val_loss, val_acc_plain, val_acc_moved)
0.3100764751434326 0.27951204776763916 0.925000011920929 0.4300000071525574

No. The lowest validation loss with shifts is 0.310, against 0.280 without them. A one-pixel move is not a small change for these images. Each pixel counts the ink in a 4-by-4 block of a 32-by-32 bitmap [2], so it moves the digit by 4 pixels of the original bitmap. The early-stopped network of Example 1 classifies 92.5% of the validation images correctly, but only 43.0% of the same images moved one pixel to the right.
