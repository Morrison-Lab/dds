1 Welcome

1.1 Plan for this lecture

The PyTorch chapter fit the soft 0-or-1 rule, a model with one parameter. This lecture builds models that learn their own features of the digits:

  1. what a stack of linear layers can and cannot compute, and what a function applied between the layers changes;
  2. how a network turns its last layer’s numbers into class probabilities and a loss, and how PyTorch computes that loss without overflowing;
  3. how much a network with one layer of learned features can represent.

2 Layers

2.1 Two layers with nothing between them

Exercise 1 (Two layers with nothing between them)

Exercise 1 (Two layers with nothing between them) A layer first = nn.Linear(64, 32) maps a digit’s 64 pixels \(\vx\) to 32 numbers \(\matr{W}_1 \vx + \vecf{b}_1\), and a layer second = nn.Linear(32, 10) maps 32 numbers \(\vecf{u}\) to 10 numbers \(\matr{W}_2 \vecf{u} + \vecf{b}_2\). What kind of function of \(\vx\) does the stack second(first(x)) compute?

Solution 1

Solution 1. Substituting the first layer into the second,

\[ \begin{aligned} \matr{W}_2 \paren{\matr{W}_1 \vx + \vecf{b}_1} + \vecf{b}_2 &= \matr{W}_2 \matr{W}_1 \vx + \matr{W}_2 \vecf{b}_1 + \vecf{b}_2 && \text{(distribute $\matr{W}_2$)} \\ &= \underbrace{\paren{\matr{W}_2 \matr{W}_1}}_{10 \times 64} \vx + \underbrace{\paren{\matr{W}_2 \vecf{b}_1 + \vecf{b}_2}}_{10 \times 1} && \text{(group the terms that do not involve $\vx$)} \end{aligned} \]

So the stack is an affine function of \(\vx\), the same kind of function as one nn.Linear(64, 10), with weight matrix \(\matr{W}_2 \matr{W}_1\) and bias \(\matr{W}_2 \vecf{b}_1 + \vecf{b}_2\). The 32 numbers in the middle add nothing that one layer could not compute.

Show code
first = nn.Linear(64, 32)
second = nn.Linear(32, 10)
weight = second.weight @ first.weight
bias = second.weight @ first.bias + second.bias
stacked = second(first(x_test))
one_layer = x_test @ weight.T + bias
stack_gap = (stacked - one_layer).abs().max().item()
print(weight.shape, bias.shape, stack_gap)
torch.Size([10, 64]) torch.Size([10]) 1.4901161193847656e-07

On the 597 test images, the stack and the single layer agree to within 1.5e-07, a rounding error. nn.Linear stores \(\matr{W}\) with one row per output, and computes x @ weight.T + bias for a tensor x with one row per image.

2.2 A function between the layers

Exercise 2 (A function between the layers)

Exercise 2 (A function between the layers) Suppose the logistic function, \(\sigmoidf{z} = 1 / \paren{1 + \e{-z}}\), is applied to each of the 32 numbers between the two layers of Exercise 1, giving second(torch.sigmoid(first(x))). Is that stack still an affine function of \(\vx\)?

Hint

An affine function \(f\) maps the midpoint of two inputs to the midpoint of their outputs: \(f\paren{\frac{1}{2}(\vx + \vx')} = \frac{1}{2}\paren{f(\vx) + f(\vx')}\). Try two digits.

Solution 2

Solution 2.

Show code
def midpoint_gap(f, a, b):
    # Largest gap between f at the midpoint and the midpoint of f.
    return (f((a + b) / 2) - (f(a) + f(b)) / 2).abs().max().item()

a, b = x_test[0], x_test[1]
gap_linear = midpoint_gap(lambda v: second(first(v)), a, b)
gap_logistic = midpoint_gap(lambda v: second(torch.sigmoid(first(v))), a, b)
mean_abs_pre = first(torch.stack([a, b])).abs().mean().item()
print(gap_linear, gap_logistic, mean_abs_pre)
5.960464477539063e-08 0.0003224015235900879 0.2633136212825775

No. Take the first two test images, which show the digits 2 and 8. For them, the stack with nothing between its layers maps their midpoint to the midpoint of their outputs, to within 6e-08, a rounding error. With \(\sigmoid\) between the layers it misses by up to 0.00032, far more than a rounding error, so it is not an affine function. The logistic gap is still small. The untrained first layer’s numbers for these two images have a mean absolute value of 0.26, and near 0, \(\sigmoid\) is close to its tangent line, \(\frac{1}{2} + \frac{z}{4}\). Training can move the numbers to where \(\sigmoid\) bends.

The logistic function bends each of the 32 numbers, so each of the 10 outputs is an affine function of 32 bent features, not of the pixels. Training moves \(\matr{W}_1\) and \(\vecf{b}_1\) as well as \(\matr{W}_2\) and \(\vecf{b}_2\), so it chooses those features.

Definition 1 (Hidden layer)

Definition 1 (Hidden layer) A hidden layer of a network is a vector that the network computes from its input on the way to its output, and that is neither the input nor the output [1, Ch. 6].

The training data give an input and a target output for each example, but no target for a hidden layer: training chooses the parameters that compute it. These notes write a hidden layer as \(\vhidval\).

Definition 3 (Activation function (nonlinearity))

Definition 3 (Activation function (nonlinearity)) An activation function, or nonlinearity, is a fixed function \(g: \reals \to \reals\), not an affine function, that a network applies to each entry of an affine function of the layer before, so that a hidden layer is

\[ \vhidval = g\paren{\matr{W} \vx + \vecf{b}}, \]

with \(g\) applied entry by entry [1, Sec. 6.3].

2.3 Three activation functions

Exercise 3 (Three activation functions)

Exercise 3 (Three activation functions) How do the logistic function \(\sigmoidf{z}\), the hyperbolic tangent \(\tanhf{z}\), and the function \(\maxf{0, z}\) behave as \(\abs{z}\) grows large?

Solution 3

Solution 3.

Show code
z = torch.linspace(-4, 4, 401)
activations = {
    "logistic": torch.sigmoid(z),
    "tanh": torch.tanh(z),
    "max(0, z)": torch.relu(z),
}
fig, ax = plt.subplots(figsize=(6, 3.5), layout="constrained")
for name, value in activations.items():
    ax.plot(z, value, label=name);
ax.axhline(0, color="gray", linewidth=0.5);
ax.set_xlabel("z");
ax.set_ylabel("g(z)");
ax.legend();
plt.show()
  • Large positive \(z\). \(\sigmoidf{z}\) levels off at 1, and \(\tanhf{z}\) levels off at 1, while \(\maxf{0, z} = z\) keeps growing.
  • Large negative \(z\). \(\sigmoidf{z}\) levels off at 0, and \(\tanhf{z}\) levels off at \(-1\), while \(\maxf{0, z}\) is exactly 0 for every negative \(z\).

\(\tanh\) is a rescaled logistic function, \(\tanhf{z} = 2 \sigmoidf{2z} - 1\), so its graph is the same S curve, centred on 0 instead of \(\frac{1}{2}\).

Definition 5 (Rectified linear unit (ReLU))

Definition 5 (Rectified linear unit (ReLU)) The rectified linear unit, or ReLU, is the activation function

\[ \operatorname{ReLU}(z) = \maxf{0, z} \]

[1, Sec. 6.3.1], [3]. PyTorch provides it as torch.relu and as the layer nn.ReLU(). In mathematics \(\maxf{0, z}\) is also called the positive part of \(z\), written \(z^+\). Deep Learning recommends ReLU as the default activation function for hidden layers [1, Sec. 6.1].

Exercise 4 (Where the slopes vanish)

Exercise 4 (Where the slopes vanish) Using automatic differentiation, find the values of \(z\) at which the derivative of each activation function of Exercise 3 is close to 0.

Solution 4

Solution 4.

Show code
z = torch.linspace(-4, 4, 401, requires_grad=True)
fig, ax = plt.subplots(figsize=(6, 3.5), layout="constrained")
slopes = {}
for name, g in [("logistic", torch.sigmoid), ("tanh", torch.tanh), ("ReLU", torch.relu)]:
    (slope,) = torch.autograd.grad(g(z).sum(), z)
    slopes[name] = slope
    ax.plot(z.detach(), slope, label=name);
ax.set_xlabel("z");
ax.set_ylabel("g'(z)");
ax.legend();
plt.show()
Show code
largest_logistic_slope = slopes["logistic"].max().item()
logistic_slope_at_4 = slopes["logistic"][-1].item()

Each output of g(z) depends only on the matching entry of z, so the gradient of g(z).sum() holds the derivative \(g'(z)\) at each point.

  • Logistic. Its derivative peaks at 0.25 at \(z = 0\), and is close to 0 once \(\abs{z}\) is large: 0.018 at \(z = 4\).
  • tanh. Its derivative peaks at 1 at \(z = 0\) and is also close to 0 for large \(\abs{z}\).
  • ReLU. Its derivative is 1 for every positive \(z\) and exactly 0 for every negative \(z\). At \(z = 0\) it has no derivative; PyTorch uses 0 there.

A unit whose pre-activation sits where the derivative is near 0 is saturated: a small change in its weights barely changes its output, so the gradient that training follows is small too. The logistic function and \(\tanh\) saturate on both sides, and ReLU only on its negative side.

2.4 Feedforward networks

Definition 6 (Feedforward network (multilayer perceptron, MLP))

Definition 6 (Feedforward network (multilayer perceptron, MLP)) A feedforward network, or multilayer perceptron (MLP), computes its output \(\vecf{\hy}\) from its input \(\vx\) through a sequence of \(K\) hidden layers,

\[ \begin{aligned} \vhidval^{(1)} &= g\paren{\matr{W}^{(1)} \vx + \vecf{b}^{(1)}}, \\ \vhidval^{(\layeridx)} &= g\paren{\matr{W}^{(\layeridx)} \vhidval^{(\layeridx - 1)} + \vecf{b}^{(\layeridx)}}, \qquad \layeridx = 2, \dots, K, \\ \vecf{\hy} &= \matr{W}^{(K + 1)} \vhidval^{(K)} + \vecf{b}^{(K + 1)}, \end{aligned} \]

where \(g\) is an activation function and the weight matrices \(\matr{W}^{(\layeridx)}\) and bias vectors \(\vecf{b}^{(\layeridx)}\) are the network’s parameters [1, Ch. 6]. Information flows from the input to the output, with no path from a later layer back to an earlier one; “feedforward” names that.

Every layer of an MLP is fully connected, so it is also called a fully connected network, and Deep Learning calls it a deep feedforward network. It contains no perceptron in Rosenblatt’s sense, a threshold function of a weighted sum [4], so the name is historical. Its depth is \(K + 1\). The last layer has no activation function; how its numbers become predictions depends on the task.

Remark 1 (Writing a layer)

Remark 1 (Writing a layer). One layer is written here as \(g\paren{\matr{W} \vx + \vecf{b}}\), with \(\vx\) a column vector and \(\matr{W}\) having one row per output. Other sources write it differently:

  • PyTorch’s nn.Linear stores \(\matr{W}\) in the same orientation, but takes a batch of inputs with one row per example, and computes x @ weight.T + bias.
  • Deep Learning writes \(g\paren{\tp{\matr{W}} \vx + \vecf{c}}\), with one column of \(\matr{W}\) per output [1, Sec. 6.1].
  • lds puts a 1 at the start of \(\vx\) and folds the bias into \(\matr{W}\).

3 Output units and losses

3.1 From scores to probabilities

Exercise 5 (From scores to probabilities)

Exercise 5 (From scores to probabilities) The MLP of Example 6 gives each image 10 real numbers, positive or negative. How can they become 10 probabilities, one per digit, each positive and adding up to 1?

Solution 5

Solution 5. Apply the softmax function: exponentiate each number, which makes it positive, then divide by the sum of the exponentials, which makes them add up to 1.

Definition 7 (Logits)

Definition 7 (Logits) The logits of a classification network are the numbers its output layer computes for each class, before the softmax function turns them into probabilities. PyTorch’s documentation uses this name.

The name comes from the logit function, the log odds, but most logits are not log odds. Adding one number to every logit leaves the softmax unchanged, so only their differences matter: with two classes, the difference \(z_2 - z_1\) is the log odds of class 2. Other names for logits are scores and unnormalized log probabilities.

Exercise 6 (The loss before training)

Exercise 6 (The loss before training) The untrained MLP of Example 6 gives each test image probabilities near \(\frac{1}{10}\). About what mean cross-entropy loss should it have on the test set?

Solution 6

Solution 6. The cross-entropy loss of one image is \(-\log\) of the probability the network gives its true class. If every probability is \(\frac{1}{10}\), every image’s loss is \(-\log \frac{1}{10} = \log 10\), and so is their mean.

Show code
start_loss = nn.functional.cross_entropy(mlp(x_test), y_test).item()
print(start_loss, np.log(10))
2.3070168495178223 2.302585092994046

nn.functional.cross_entropy takes the logits and the true digits, and returns the mean loss over the test set, 2.307, close to \(\log 10 \approx 2.303\). A training run whose first loss is far from \(\log C\), for \(C\) classes, is worth checking for a bug before it runs further.

Exercise 8 (The log of a softmax probability)

Exercise 8 (The log of a softmax probability) The cross-entropy loss needs \(\log \operatorname{softmax}(\vz)_m\), not the probability itself. Write \(\log \operatorname{softmax}(\vz)_m\) without a fraction.

Solution 8

Solution 8. \[ \begin{aligned} \log \operatorname{softmax}(\vz)_m &= \log \frac{\e{z_m}}{\sumto{k}{C} \e{z_k}} && \text{(the softmax function)} \\ &= \log \e{z_m} - \log \sumto{k}{C} \e{z_k} && \text{(log of a quotient)} \\ &= z_m - \log \sumto{k}{C} \e{z_k} && \text{($\log$ undoes $\expt$)} \end{aligned} \]

The first term needs no exponential at all. Only the second, the log of a sum of exponentials, can still overflow.

Definition 8 (Log-sum-exp)

Definition 8 (Log-sum-exp) The log-sum-exp function maps a vector \(\vz \in \reals^C\) to

\[ \operatorname{LSE}(\vz) = \log \sumto{k}{C} \e{z_k} \]

[1, Sec. 6.2.2.3]. It is the log of the denominator of the softmax function. PyTorch provides it as torch.logsumexp. \(\operatorname{LSE}\) is differentiable. \(\operatorname{LSE}(\vz)\) is at least the largest entry of \(\vz\) and at most that entry plus \(\log C\). So it is called a smooth maximum.

Theorem 1 (Log softmax) For \(\vz \in \reals^C\) and \(m = 1, \dots, C\),

\[ \log \operatorname{softmax}(\vz)_m = z_m - \operatorname{LSE}(\vz). \]

Proof

Proof. By Solution 8 and Definition 8.

Exercise 9 (Computing log-sum-exp without overflow)

Exercise 9 (Computing log-sum-exp without overflow) Let \(c\) be any number. Write \(\operatorname{LSE}(\vz)\) in terms of \(c\) and \(\operatorname{LSE}\) of the shifted vector \(\vz - c\), whose entries are \(z_k - c\).

Solution 9

Solution 9. \[ \begin{aligned} \operatorname{LSE}(\vz) &= \log \sumto{k}{C} \e{z_k} && \text{(definition of $\operatorname{LSE}$)} \\ &= \log \sumto{k}{C} \e{c} \e{z_k - c} && \text{(add and subtract $c$ in each exponent)} \\ &= \log \paren{\e{c} \sumto{k}{C} \e{z_k - c}} && \text{(take $\e{c}$ out of the sum)} \\ &= c + \log \sumto{k}{C} \e{z_k - c} && \text{(log of a product)} \\ &= c + \operatorname{LSE}(\vz - c) && \text{(definition of $\operatorname{LSE}$)} \end{aligned} \]

Theorem 2 (Shifting log-sum-exp)

Theorem 2 (Shifting log-sum-exp) For \(\vz \in \reals^C\) and any \(c \in \reals\),

\[ \operatorname{LSE}(\vz) = c + \operatorname{LSE}(\vz - c). \]

Proof

Proof. By Solution 9.

Exercise 10 (Choosing the shift)

Exercise 10 (Choosing the shift) Which \(c\) in Theorem 2 keeps every exponential in \(\operatorname{LSE}(\vz - c)\) from overflowing?

Solution 10

Solution 10. Take \(c = \max_k z_k\). Then every exponent \(z_k - c\) is at most 0, so no exponential exceeds 1. One exponent is exactly 0, so the sum is at least 1, and its log is not \(-\infty\).

Remark 2 (Why PyTorch’s cross-entropy takes logits)

Remark 2 (Why PyTorch’s cross-entropy takes logits). nn.CrossEntropyLoss and nn.functional.cross_entropy take logits, not probabilities. They compute the log probabilities by Theorem 1, with the shift of Theorem 2, so the loss stays finite for any logits. A classification network built for them ends with a linear layer and no softmax: softmax is applied only when probabilities are wanted for their own sake, as in Solution 5. Putting nn.Softmax at the end of the network and then calling nn.CrossEntropyLoss applies softmax twice.

3.3 Other kinds of output

Exercise 11 (An output layer for two classes)

Exercise 11 (An output layer for two classes) An MLP is to tell 0s from 1s, predicting the probability that a digit is a 1. What should its output layer compute?

Solution 11

Solution 11. One number \(z\), the logit of a 1, turned into a probability by the logistic function, \(\sigmoidf{z}\). That is the soft 0-or-1 rule of the PyTorch chapter, with \(z\) computed by a network instead of from one feature.

Two outputs with softmax would also work, but they carry one number too many: \(\operatorname{softmax}(z_1, z_2)_2 = \sigmoidf{z_2 - z_1}\), so only the difference of the two logits matters.

Exercise 12 (A loss for two classes)

Exercise 12 (A loss for two classes) What loss should training minimize for the output layer of Solution 11?

Solution 12

Solution 12. Use the log loss, which is the cross-entropy loss for two classes. PyTorch’s nn.BCEWithLogitsLoss takes the logit \(z\) itself, for the reason of Remark 2.

Exercise 13 (An output layer for a number)

Exercise 13 (An output layer for a number) An MLP is to predict a car’s fuel economy in miles per gallon. What should its output layer compute?

Solution 13

Solution 13. One number, with no activation function: any real number can be a prediction, and squashing it with the logistic function or the ReLU would rule some out.

Exercise 14 (A loss for a number)

Exercise 14 (A loss for a number) What loss should training minimize for the output layer of Solution 13?

Solution 14

Solution 14. Use the mean squared error, PyTorch’s nn.MSELoss. Minimizing the mean squared error is maximum likelihood when the output is the mean of a normal distribution with a fixed variance [1, Sec. 6.2.2.1], just as the cross-entropy loss is maximum likelihood for the probabilities of the classes.

Remark 3 (Output layers and their losses)

Remark 3 (Output layers and their losses). Solution 5, Solution 11 and Solution 13 pair each kind of target with an output layer and a loss, each the negative log-likelihood of a distribution for the target [1, Sec. 6.2.2]:

One of 2 classes One logit, logistic function Bernoulli nn.BCEWithLogitsLoss

4.2 Bends in a ReLU network

Exercise 16 (The shape of a small ReLU network)

Exercise 16 (The shape of a small ReLU network) An MLP has one input \(z \in \reals\), one hidden layer of \(L\) ReLU units, and one output with no activation function:

\[ \hy = c + \sumto{i}{L} v_i \maxf{0, w_i z + b_i}. \]

What does the graph of \(\hy\) against \(z\) look like?

Solution 16

Solution 16. For \(w_i \neq 0\), unit \(i\) is 0 on one side of \(z = -b_i / w_i\) and the line \(w_i z + b_i\) on the other, so its graph is two straight pieces that meet at that point. A weighted sum of such graphs, plus a constant, is still made of straight pieces. It can change slope only where some unit does. So the graph of \(\hy\) is a connected chain of straight pieces, with at most \(L\) bends.

Show code
_ = torch.manual_seed(3)
tiny = nn.Sequential(nn.Linear(1, 3), nn.ReLU(), nn.Linear(3, 1))
z = torch.linspace(-3, 3, 601).unsqueeze(1)
with torch.no_grad():
    y_hat = tiny(z)
    bends = (-tiny[0].bias / tiny[0].weight.squeeze()).numpy()
fig, ax = plt.subplots(figsize=(6, 3.5), layout="constrained")
ax.plot(z, y_hat);
for bend in bends:
    ax.axvline(bend, color="gray", linestyle=":");
ax.set_xlabel("z");
ax.set_ylabel("network output");
plt.show()

For a random network with \(L = 3\), the dotted lines mark the three points \(-b_i / w_i\), and the graph bends at each one that lies in the plotted range.

Exercise 17 (Following any curve)

Exercise 17 (Following any curve) Let \(f\) be a continuous function on an interval \([a, b]\). Could a network like the one in Exercise 16 follow \(f\) as closely as you like?

Solution 17

Solution 17. Yes, with enough units. Mark points on the graph of \(f\) at closely spaced values of \(z\), and join neighbouring points with straight lines. Because \(f\) is continuous on a closed interval, it changes little between nearby points, so the joined-up graph stays as close to \(f\) as you like once the points are close enough together. Call the inner points \(t_1 < \dots < t_{n - 1}\), and the slopes of the \(n\) pieces \(s_1, \dots, s_n\). A network like the one in Exercise 16 draws the joined-up graph on \([a, b]\) with \(n\) units, one per piece, each with \(w_i = 1\):

  • \(c = f(a)\) starts the graph at the first point;
  • the unit \(s_1 \maxf{0, z - a}\) gives the first piece its slope;
  • for each inner point \(t_j\), the unit \(\paren{s_{j + 1} - s_j} \maxf{0, z - t_j}\) is 0 to the left of \(t_j\), and changes the slope from \(s_j\) to \(s_{j + 1}\) at \(t_j\).

Theorem 3 (Universal approximation)

Theorem 3 (Universal approximation) Let \(g\) be a continuous activation function that is not a polynomial, such as the logistic function or the ReLU. For every continuous function \(f\) on a closed and bounded set \(\mathcal{X} \subset \reals^{\inputdim}\) and every \(\epsilon > 0\), there is a width \(L\) and parameters \(\vw_i \in \reals^{\inputdim}\) and \(b_i, v_i, c \in \reals\) such that

\[ \abs{f(\vx) - \paren{c + \sumto{i}{L} v_i \, g\paren{\tp{\vw_i} \vx + b_i}}} < \epsilon \quad \text{for every } \vx \in \mathcal{X}. \]

[1, Sec. 6.4.1], [5].

Proof

Proof. For one input and the ReLU, Solution 17 gives the idea. Cybenko [6] proved the theorem for logistic-shaped activation functions, Hornik [7] for bounded nonconstant ones, and Leshno et al. [5] for every activation function that is not a polynomial; those proofs need more analysis than these notes assume.

Example 11 (Universal approximation for one input)

Example 11 (Universal approximation for one input) For one input, the ReLU and a closed interval \([a, b]\), Solution 17 builds the network that Theorem 3 promises: it joins points on the graph of \(f\) with straight pieces, and gives the network one unit for each piece. Making the pieces shorter brings the network closer to \(f\), at the cost of more units.

n_steps = 3000


def fit_width(width, steps=n_steps):
    # Fit a one-hidden-layer ReLU network of `width` units to mpg on horsepower.
    torch.manual_seed(2)
    net = nn.Sequential(nn.Linear(1, width), nn.ReLU(), nn.Linear(width, 1))

        loss = nn.functional.mse_loss(net(hp_scaled), mpg)
        loss.backward()
        optimizer.step()
    return net, loss.item()

The Auto data hold 392 cars from the UCI Auto MPG dataset [8], from a local copy, data/auto.csv, of the version in lds. Each network fits miles per gallon on horsepower, rescaled to mean 0 and standard deviation 1, by 3,000 steps of gradient descent on the mean squared error. With 1 unit the fit can bend only once, and its training mean squared error is 19.6. With 3 units it is 18.5, and with 20 it is 18.4. So the error falls as the network gets wider. Theorem 3 says that a wide enough network can follow any continuous curve; it does not say that following the training data more closely predicts new cars better.

Remark 4 (What universal approximation leaves out)

Remark 4 (What universal approximation leaves out). Theorem 3 says that some network of one hidden layer comes within \(\epsilon\) of \(f\). It does not say how wide that network must be, a width that can grow very fast with the number of inputs \(\inputdim\), nor that training finds its parameters, nor that it predicts new data well [1, Sec. 6.4.1].

Depth helps with the first of these. A ReLU network’s graph is made of straight pieces, as Solution 16 showed for one input. For networks with the same total number of units, the number of pieces a deep network can make grows exponentially with its number of layers, while a network with one hidden layer makes far fewer [9]. Some functions with many pieces therefore need far fewer units in a network with several layers.
