1 Welcome

1.1 Plan for this lecture

Deep learning reuses the pieces of supervised learning from DATA 371 and DATA 471, which lds covers in full. This lecture reviews three of them on the handwritten digits from the course overview, then shows where each one reappears in deep learning:

  1. the parts of a learning problem: a set of candidate rules, the parameters that pick one out, and a loss function;
  2. why models are trained on a smooth loss rather than on their error rate;
  3. why a model is judged on data it was not fit to.

1.2 The digits again

The exercises here use the 1,797 handwritten digits that the course overview loads from the UCI Machine Learning Repository [1], from the same local copy, data/optdigits-test.csv. They also use two of its features, each an average of an 8 by 8 image’s pixels, with rows and columns counted from 0:

  • center ink, over rows 2 to 5 and columns 3 and 4;
  • left ink, over rows 2 to 5 and columns 0 to 2.

2 The parts of a learning problem

2.1 Candidate rules and their parameter

Exercise 1 (What the 0-or-1 rule chose among)

Exercise 1 (What the 0-or-1 rule chose among) The course overview’s rule for 0 or 1 calls an image a 1 when its center ink is above a cutoff, and found its cutoff by trying every value from 0 to 16 in steps of 0.5. What set of rules did that search choose among?

Solution 1

Solution 1. Every rule of the form “a 1 when the center ink is above \(\param\), and a 0 otherwise”, one rule for each number \(\param\). The number \(\param\) that picks one rule out of this set is the rule’s one parameter. A deep network picks one function out of a much larger set, with many parameters instead of one.

2.2 The loss

Exercise 2 (How the 0-or-1 rule chose)

Exercise 2 (How the 0-or-1 rule chose) By what criterion did the search of Exercise 1 pick one cutoff over another?

Solution 2

Solution 2. It kept the cutoff that got the fewest images wrong. Counting mistakes uses the 0-1 loss function: 1 for a wrong label and 0 for a right one. Its average over the images is the rule’s error rate, which is the rule’s empirical risk under that loss. Choosing the parameter with the lowest empirical risk is empirical risk minimization, and deep networks are fit the same way.

Exercise 3 (The error rate against the cutoff)

Exercise 3 (The error rate against the cutoff) Among the 0s and 1s, plot the error rate of the 0-or-1 rule against its cutoff \(\param\), for every \(\param\) from 0 to 16 in steps of 0.01.

Solution 3

Solution 3.

is_01 = (labels == 0) | (labels == 1)

Exercise 4 (Fitting by following the error rate) Could gradient descent find the best cutoff by following the slope of the curve in Figure 1?

Solution 4

Solution 4.

Show code
print(len(np.unique(ink_01)))
99

No. The curve in Figure 1 is a staircase. The error rate changes only where \(\param\) crosses one of the 99 values that the center ink takes, and it is flat everywhere in between, so its slope is 0 wherever the slope exists. Gradient descent would never move.

The grid of cutoffs in steps of 0.01 reaches the lowest error rate, 2.2% (8 of the 360 images), on 3 separate stretches between 5.63 and 6.49, and it found them by trying each cutoff in turn. That works for one parameter, but a network has thousands of weights, and trying every combination of their values is out of reach.

3.2 A smooth loss

Exercise 5 (The log loss against the cutoff)

Exercise 5 (The log loss against the cutoff) Swap the 0-or-1 rule for a soft version, which gives each image a probability of being a 1:

\[\hprob = \sigmoidf{\predvar - \param},\]

where

  • \(\predvar\) is the image’s center ink,
  • \(\param\) is the cutoff, the rule’s one parameter,
  • \(\sigmoid\) is the logistic function, \(\sigmoidf{z} = 1 / (1 + \expf{-z})\),
  • and \(\hprob\) is the probability the rule gives that the image is a 1.

Among the 0s and 1s, plot the mean log loss of this rule against \(\param\), over the cutoffs of Exercise 3.

Solution 5

Solution 5.

Show code
def mean_log_loss(c):
    """Mean log loss of the soft 0-or-1 rule with cutoff `c`."""
    p = 1 / (1 + np.exp(-(ink_01 - c)))
    return -np.mean(np.where(is_one, np.log(p), np.log(1 - p)))

log_loss = np.array([mean_log_loss(c) for c in cutoffs])

fig, ax = plt.subplots(figsize=(6, 3), layout="constrained")
ax.plot(cutoffs, log_loss)
ax.set_xlabel(r"cutoff $\theta$ on center ink")
ax.set_ylabel("mean log loss")
plt.show()

Exercise 6 (Fitting by following the log loss)

Exercise 6 (Fitting by following the log loss) Could gradient descent find the best cutoff by following the slope of the curve in Figure 2?

Solution 6

Solution 6.

Show code
c_log = cutoffs[log_loss.argmin()]
error_at_c_log = np.mean((ink_01 > c_log) != is_one)
print(c_log, log_loss.min(), error_at_c_log)
6.6000000000000005 0.053815807670509946 0.030555555555555555

Yes. The curve in Figure 2 is smooth, with one lowest point. Its slope is nonzero at every other cutoff, so a step against the slope always goes downhill, and gradient descent has a direction to follow.

The lowest log loss is at \(\param\) = 6.60. The hard rule with that cutoff gets 11 of the 360 images of 0s and 1s wrong, against 8 for the best cutoffs in Solution 4. Minimizing the log loss does not minimize the error rate, but, unlike the error rate, it can be minimized by gradient descent.

Deep networks are trained the same way: on a smooth loss such as the log loss, which is also called cross-entropy, while their error rate or accuracy is what gets reported.

4 Judging a model

4.1 Held-out data

Exercise 7 (The digit-average rule on new images)

Exercise 7 (The digit-average rule on new images) The course overview’s digit-average rule labels an image with the digit whose average (center ink, left ink) is nearest, and it was scored on the same images the averages came from. Split the 1,797 images at random into two halves, a training set and a test set. Compute the digit averages from the training set only. What share of each set does the rule get right?

Solution 7

Solution 7.

Show code
rng = np.random.default_rng(481)
order = rng.permutation(len(labels))
train, test = order[: len(labels) // 2], order[len(labels) // 2 :]
hand_features = np.column_stack([center_ink, left_ink])

def accuracy(predicted, actual):
    return np.mean(predicted == actual)

def nearest(points, references):
    """Index of the nearest row of `references` to each row of `points`."""
    distances = ((points[:, None, :] - references[None, :, :]) ** 2).sum(axis=2)
    return distances.argmin(axis=1)

means = np.array(
    [hand_features[train][labels[train] == k].mean(axis=0) for k in range(10)]
)
acc_mean_train = accuracy(nearest(hand_features[train], means), labels[train])
acc_mean_test = accuracy(nearest(hand_features[test], means), labels[test])
print(len(train), len(test), round(acc_mean_train, 3), round(acc_mean_test, 3))
898 899 0.468 0.485

The rule gets 46.8% of the training set right and 48.5% of the test set. The two shares are close: ten digit averages, twenty numbers in all, leave the rule little room to fit the training set’s quirks, so its training error says roughly what its test error will be. The test share came out a little higher only by the luck of this split; another random split could put it a little lower.

Exercise 8 (A rule that memorizes)

Exercise 8 (A rule that memorizes) Now make the rule far more flexible: label each image with the digit of the training image nearest to it in (center ink, left ink). This is one-nearest-neighbor classification. Using the split from Solution 7, what share of the training set and of the test set does it get right?

Solution 8

Solution 8.

Show code
train_features = hand_features[train]
acc_nn_train = accuracy(
    labels[train][nearest(train_features, train_features)], labels[train]
)
acc_nn_test = accuracy(
    labels[train][nearest(hand_features[test], train_features)], labels[test]
)
print(round(acc_nn_train, 3), round(acc_nn_test, 3))
0.964 0.415

The rule gets 96.4% of the training set right, but only 41.5% of the test set, worse than the 48.5% of the digit-average rule in Solution 7. On the training set, each image’s nearest neighbor is usually itself, so the rule mostly recalls labels it has already seen. It falls short of 100% only where images of different digits share both feature values.

This rule has learned the training images themselves rather than what the digits look like, which lds calls overfitting. Deep networks are flexible enough to memorize their training sets too, even when the labels are assigned at random [2], so these notes judge every network on images it was not trained on.
