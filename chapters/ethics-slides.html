1 Welcome

1.1 Plan for this lecture

Earlier chapters asked how well a network does. This lecture asks four other questions about a trained network:

  1. whose errors it makes;
  2. what it gives away about its training set;
  3. what training it costs;
  4. what its users should be told about it.

Ethics and Fairness in the DATA 471 notes covers bias, definitions of fairness and the result that they cannot all hold at once; this lecture links to it rather than repeating it.

1.2 The digits

Show code
import numpy as np
import pandas as pd
import torch
from torch import nn
import matplotlib.pyplot as plt

digits = pd.read_csv("data/optdigits-test.csv", header=None)
x = torch.tensor(digits.iloc[:, :64].to_numpy(), dtype=torch.float32) / 16
y = torch.tensor(digits[64].to_numpy())
order = torch.randperm(len(x), generator=torch.Generator().manual_seed(481))
train_idx, val_idx = order[:1000], order[1000:]
n_train, n_val = len(train_idx), len(val_idx)
loss_fn = nn.CrossEntropyLoss()
default_width, default_steps = 64, 300


def fit(rows, width=default_width, seed=0, n_steps=default_steps):
    # A network with one hidden layer, trained by full-batch Adam on the given rows.
    torch.manual_seed(seed)
    net = nn.Sequential(nn.Linear(64, width), nn.ReLU(), nn.Linear(width, 10))
    optimizer = torch.optim.Adam(net.parameters(), lr=0.01)
    for step in range(n_steps):
        optimizer.zero_grad()
        loss_fn(net(x[rows]), y[rows]).backward()
        optimizer.step()
    return net


def correct(net, rows):
    with torch.no_grad():
        return (net(x[rows]).argmax(dim=1) == y[rows]).float()


def accuracy(net, rows):
    return correct(net, rows).mean().item()


def digit_accuracy(net, rows):
    # The share of each digit's images that the network classifies correctly.
    return pd.Series(correct(net, rows).numpy()).groupby(y[rows].numpy()).mean()


print(n_train, n_val)
1000 797

The examples use the 1,797 digits of data/optdigits-test.csv, each an 8 by 8 image, written by 13 people [1]. 1,000 random images form a training set, and the other 797 form a validation set. fit() trains a network with one hidden layer of ReLU units, 64 of them unless width says otherwise, on the given rows by 300 steps of full-batch Adam. accuracy() gives the share of the rows that a network classifies correctly, and digit_accuracy() gives that share for each digit separately.

2 Who the errors fall on

2.1 Too few eights

Exercise 1 (Too few eights)

Exercise 1 (Too few eights) A network is trained on the training set with all but 10 of its eights removed. Would its accuracy on the whole validation set show that it has trouble with eights?

Solution 1

Solution 1.

Hardly. The training set holds 100 eights. Trained on all of them, the network classifies 96.0% of the validation digits correctly; trained on 10 of them, 94.1%. On the 74 eights of the validation set alone, its accuracy falls from 91% to 69%. Eights are only 9% of the validation set, so a large drop on them is a small drop overall.

Definition 1 (Disaggregated evaluation)

Definition 1 (Disaggregated evaluation) A disaggregated evaluation reports a model’s performance separately for each group of its inputs, such as each group of people or each condition the inputs were recorded under, as well as over the whole evaluation set [2, Sec. 4.7].

Table 1 is a disaggregated evaluation of the two networks, with the digits as the groups. Removing eights lowers the accuracy on eights most. Even the network trained on every eight does better on some digits than on others, from 89% on 3s to 100% on 7s. Each digit has between 73 and 94 images in the validation set, so one image moves a digit’s accuracy by more than one percentage point, and differences of a point or two between digits could change with another random split.

Remark 1 (The same failure with people)

Remark 1 (The same failure with people). A training set with few eights is a small case of what Ethics and Fairness in the DATA 471 notes calls representation bias: a group that appears less often in the training set can get less of the network’s accuracy. Among its documented cases, Buolamwini and Gebru [3] evaluated commercial face-analysis systems separately on groups of faces and found error rates far higher for darker-skinned women than for lighter-skinned men; the benchmarks that the systems’ accuracy was usually reported on held mostly lighter-skinned faces.

3 What a network remembers

3.1 Guessing the training set

Exercise 2 (Guessing the training set)

Exercise 2 (Guessing the training set) Someone has a trained network and one digit image, but not the network’s training set. How could they guess whether that image was in the training set?

Solution 2

Solution 2. Compute the network’s loss on the image. Training pushes the loss down on the training images themselves, so an image with an unusually small loss is more likely to be one of them.

Show code
members, outsiders = order[:100], order[100:200]
target_width = 256
target = fit(members, width=target_width)
per_image_loss = nn.CrossEntropyLoss(reduction="none")


def losses(net, rows):
    with torch.no_grad():
        return per_image_loss(net(x[rows]), y[rows])


member_loss, outsider_loss = losses(target, members), losses(target, outsiders)
member_acc, outsider_acc = accuracy(target, members), accuracy(target, outsiders)
n_members = len(members)
loss_ratio = (outsider_loss.median() / member_loss.median()).item()
outsiders_above = (outsider_loss > member_loss.max()).float().mean().item()
member_log = member_loss.clamp(min=1e-8).log10()
outsider_log = outsider_loss.clamp(min=1e-8).log10()
n_members_floor = (member_log == -8).sum().item()
print(member_loss.median().item(), outsider_loss.median().item(), member_acc, outsider_acc)

Here a network with a hidden layer of 256 units is trained on 100 digits, and compared on those and on 100 others. Its median cross-entropy loss is 5.6 times larger on the digits it was not trained on. 41% of those other digits have a larger loss than any digit it was trained on, as Figure 1 shows.

Definition 2 (Membership inference attack)

Definition 2 (Membership inference attack) A membership inference attack uses a trained model’s outputs on a data point to guess whether that point was in the model’s training set [4].

Example 2 (Attacks on machine learning services)

Example 2 (Attacks on machine learning services) Shokri et al. [4, Sec. I] ran membership inference attacks on classifiers trained by Google’s and Amazon’s machine learning services, which do not reveal the models they train. Against those models, their attacks guessed membership with a median accuracy of 94% and 74%. On a data set of hospital stays in Texas, where knowing that a record was in the training set is itself sensitive, their attack was right over 70% of the time.

Exercise 3 (Where to draw the line)

Exercise 3 (Where to draw the line) The attacker of Exercise 2 knows how the network was trained: its architecture, its width, its number of training steps, and that it saw 100 digits. The attacker does not know which loss counts as small for this network. How could the attacker choose a threshold?

Solution 3

Solution 3. Train a shadow network of the same kind on 100 digits of the attacker’s own, and take the largest loss of the shadow network on those digits as the threshold. Then guess that an image was in the target’s training set when the target’s loss on it is at most the threshold.

Show code
shadow_rows = order[1000:1100]
shadow = fit(shadow_rows, width=target_width, seed=1)
threshold = losses(shadow, shadow_rows).max()
flagged_members = (member_loss <= threshold).sum().item()
flagged_outsiders = (outsider_loss <= threshold).sum().item()
attack_acc = (flagged_members + n_members - flagged_outsiders) / (2 * n_members)
flagged_share_members = flagged_members / (flagged_members + flagged_outsiders)
print(threshold.item(), flagged_members, flagged_outsiders, attack_acc, flagged_share_members)
0.0010065733222290874 100 63 0.685 0.6134969325153374
Show code
# Stop the render if the prose below stops being true.
assert 0.6 < attack_acc < 0.8

This membership inference attack flags 100 of the target’s 100 training digits and 63 of the 100 others. On the 200 digits together it guesses right 68% of the time, where a coin would guess right 50% of the time, but only 61% of the digits it flags were in the training set. It works because the target overfits: it was trained on only 100 digits, is right on 100% of them and on 92% of the others, and the attacker knew how it was trained and had digits from the same 13 writers. Shokri et al. [4] train many shadow models and a classifier on their outputs, and Yeom et al. [5] guess from the loss alone; this solution joins the two ideas in the simplest way.

Remark 2 (Overfitting and memorization)

Remark 2 (Overfitting and memorization). Yeom et al. [5, Sec. 3.2] show that if an attack guesses “trained on” whenever a classifier is right, the share of training points it flags minus the share of other points it flags equals the classifier’s generalization gap in accuracy. The network of Solution 2 is right on 100% of its training digits and 92% of the others, so that guess is right 54% of the time on a half-and-half set. A network that overfits gives away more about its training set.

Large language models can give away the training text itself, as Ethics and Fairness in the DATA 471 notes describes; Carlini et al. [6] found text that appeared in only one document of GPT-2’s training data among its outputs.

4 What training costs

4.1 Energy for GPT-3

Exercise 4 (Energy to train GPT-3)

Exercise 4 (Energy to train GPT-3) Table 4 of Patterson et al. [7] gives these figures for training GPT-3:

  • \(3.14 \times 10^{23}\) floating-point operations in all;
  • \(24.6 \times 10^{12}\) operations a second on each of its V100 GPUs;
  • 330 watts drawn by each GPU, counting its share of the memory, fans and host computer.

How much electrical energy did the GPUs use?

Solution 4

Solution 4.

Show code
flops, flops_per_second, watts = 3.14e23, 24.6e12, 330
gpu_seconds = flops / flops_per_second
gpu_years = gpu_seconds / (365.25 * 24 * 3600)
days_on_10k = gpu_seconds / 10_000 / (24 * 3600)
joules = gpu_seconds * watts
gpu_mwh = joules / 3.6e9


def sci(value):
    # A number as LaTeX scientific notation with 3 significant digits.
    mantissa, exponent = f"{value:.2e}".split("e")
    return f"${mantissa} \\times 10^{{{int(exponent)}}}$"


seconds_text, joules_text = sci(gpu_seconds), sci(joules)
print(seconds_text, gpu_years, days_on_10k, joules_text, gpu_mwh)
$1.28 \times 10^{10}$ 404.473966406711 14.773411623005119 $4.21 \times 10^{12}$ 1170.0542005420054

Dividing the operations by the rate gives \(1.28 \times 10^{10}\) GPU-seconds, about 404 GPU-years, or 14.8 days on 10,000 GPUs. At 330 watts each, the GPUs used \(4.21 \times 10^{12}\) joules. A megawatt-hour is \(3.6 \times 10^9\) joules, so that is 1,170 megawatt-hours.

Definition 3 (Power usage effectiveness (PUE))

Definition 3 (Power usage effectiveness (PUE)) The power usage effectiveness, or PUE, of a datacenter is the energy it uses in all divided by the energy its computing equipment uses [7, Sec. 2.3].

Example 3 (Two datacenters)

Example 3 (Two datacenters) Patterson et al. [7, Sec. 2.3] give 1.58 as the average PUE of datacenters in the United States in 2018, and 1.11 for the Google datacenter in Iowa where they trained one of their models. For each kilowatt-hour its computers used, the Iowa datacenter used 1.11 in all; the other 0.11 was overhead beyond powering the computing equipment.

Exercise 5 (Carbon from training GPT-3)

Exercise 5 (Carbon from training GPT-3) Table 4 of Patterson et al. [7] also gives:

  • a PUE of 1.10 for the datacenter that trained GPT-3;
  • 0.429 kilograms of carbon dioxide equivalent per kilowatt-hour, the average for electricity in the United States that they use for GPT-3.

How many tonnes of carbon dioxide equivalent did training GPT-3 emit?

Solution 5

Solution 5.

Show code
pue, kg_co2e_per_kwh = 1.10, 0.429
total_mwh = gpu_mwh * pue
tonnes_co2e = total_mwh * 1000 * kg_co2e_per_kwh / 1000
round_trips = tonnes_co2e / 180
print(total_mwh, tonnes_co2e, round_trips)
1287.059620596206 552.1485772357723 3.067492095754291

Multiplying the 1,170 megawatt-hours of Solution 4 by the PUE gives 1,287 megawatt-hours for the whole datacenter, the estimate Patterson et al. [7] report. At 0.429 kilograms per kilowatt-hour, that is 552 tonnes of carbon dioxide equivalent, about 3 times the 180 tonnes they give for a jet’s round trip between San Francisco and New York.

Remark 3 (What sweeps cost)

Remark 3 (What sweeps cost). A sweep multiplies the cost of training by the number of trials. Strubell et al. [8] add up one research project that ran 123 small hyperparameter grid searches, 4,789 training runs in all, which used 27 GPU-years over six months. They recommend that papers report training time and how sensitive a model is to its hyperparameters [8, Sec. 5], so that readers can weigh what a result cost. Patterson et al. [7] find that the choice of model, datacenter and processor can change the carbon footprint of training by up to 100 to 1,000 times. Running Deep Learning Experiments shows how to plan a sweep so that each trial answers a question.

5 Documenting a model

5.1 What a user needs to know

Exercise 6 (What a user needs to know)

Exercise 6 (What a user needs to know) The network of Solution 1 trained on every eight is about to be shared. What should someone deciding whether to use it be told?

Solution 6

Solution 6. What it is, what it was trained on, what it is meant for, how well it does, on which inputs it does worse, and what it was never tested on. A single accuracy answers only the fourth. Its training set and validation set hold digits from the same 13 writers, so how well it reads another person’s handwriting is unknown, and its users should be told so.

Definition 4 (Model card)

Definition 4 (Model card) A model card is a short document released with a trained model that reports its intended uses and its performance, including disaggregated evaluations over the groups that matter for those uses [2]. Mitchell et al. [2, Sec. 4] suggest nine sections:

  • model details;
  • intended use;
  • factors, the groups or conditions the performance may depend on;
  • metrics;
  • evaluation data;
  • training data;
  • quantitative analyses;
  • ethical considerations;
  • caveats and recommendations.

Example 4 (A model card for the digit network)

Example 4 (A model card for the digit network)  

Show code
n_params = sum(p.numel() for p in full_net.parameters())
print(n_params, full_acc, full_by_digit.min(), full_by_digit.max(), most_images)
4810 0.9598494172096252 0.8947368 1.0 94

A model card for the network of Solution 1 trained on every eight:

  • Model details: a network with one hidden layer of 64 ReLU units, 4,810 parameters, trained by full-batch Adam for 300 steps, for these notes.
  • Intended use: teaching. It is not meant for reading real handwriting, such as on forms or checks.
  • Factors: the digit, and the writer, which the data do not record.
  • Metrics: accuracy, overall and for each digit.
  • Evaluation data: 797 random images from data/optdigits-test.csv [1].
  • Training data: the other 1,000 images of the same file, from the same 13 writers.
  • Quantitative analyses: 96% correct overall, and from 89% on 3s to 100% on 7s (Table 1).
  • Ethical considerations: the images record the handwriting of 13 people and nothing else about them.
  • Caveats and recommendations: untested on other writers’ handwriting; each digit has at most 94 validation images, so the accuracy for each digit could move by a few percentage points with a different split.

Definition 5 (Datasheet)

Definition 5 (Datasheet) A datasheet for a data set is a document that answers questions about seven topics [9, Sec. 3]:

  • why the data set was made;
  • what it holds;
  • how it was collected;
  • how it was cleaned and labelled;
  • what it should and should not be used for;
  • how it is distributed;
  • who maintains it.

Example 5 (A datasheet for the digits)

Example 5 (A datasheet for the digits) Part of a datasheet for the digits of this page, from the description that comes with them [1]:

  • Why: the description does not say; the first use it lists is a 1995 thesis on combining classifiers to recognize handwritten digits.
  • What: 5,620 images of digits in all, each an 8 by 8 grid of counts from 0 to 16, with its digit as the label. 43 people wrote them: 30 wrote the 3,823 training images, and 13 others wrote the 1,797 test images used on this page. No other facts about the writers are recorded.
  • Collection: the digits were written on a preprinted form, and programs from the United States National Institute of Standards and Technology turned them into 32 by 32 bitmaps.
  • Cleaning: each 32 by 32 image was cut into 4 by 4 blocks, and the number of on pixels in each block counted.
  • Uses: the authors kept the test writers apart from the training writers, to measure accuracy on new writers.
  • Distribution: the UCI Machine Learning Repository, under a CC BY 4.0 license.

The description does not say who maintains the data. A model card for a network trained on these digits can point to this datasheet for its training and evaluation data.
