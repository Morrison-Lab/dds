1 Welcome

1.1 Plan for this lecture

The language models chapter predicted each next character with a GRU, which carries everything it knows about the earlier characters in one hidden state. This lecture builds a network that looks back at every earlier character directly:

  1. a weighted average whose weights the network computes from the inputs;
  2. that average applied within one sequence, and the order information it loses;
  3. several such averages side by side;
  4. a block that stacks them with the layers of the earlier chapters;
  5. a language model built from those blocks, trained on the same text as the GRU.

A chapter of the DATA 371/471 notes builds the same weighted averages from word vectors, without code.

2 Weighted averages

2.1 A weighted average

ExrExercise 1 (A weighted average chosen by the input)

Exercise 1 (A weighted average chosen by the input) Take the query \(\vq = (1, 0)\) and three keys with one value each:

Key Value
\((2, 0)\) 10
\((0, 2)\) 20
\((1, 1)\) 30

What weighted average of the values do you get when the weights are the softmax of the keys’ dot products with \(\vq\)?

TipHint

Score each key by its dot product with \(\vq\), then take the softmax of the three scores.

SolutionSolution 1

Solution 1.

Show code
q = torch.tensor([1.0, 0.0])
keys = torch.tensor([[2.0, 0.0], [0.0, 2.0], [1.0, 1.0]])
values = torch.tensor([10.0, 20.0, 30.0])
scores = keys @ q
weights = torch.softmax(scores, dim=0)
average = weights @ values
weight_list = weights.tolist()
print(scores, weights, average)
tensor([2., 0., 1.]) tensor([0.6652, 0.0900, 0.2447]) tensor(15.7949)

The scores are 2, 0 and 1. The softmax turns them into the weights 0.665, 0.090 and 0.245, which sum to 1. The weighted average of the values is 15.79. The first key points the same way as the query, so its value gets the largest weight, and the second key is at right angles to the query, so its value gets the smallest.

DefDefinition 1 (Scaled dot-product attention)

Definition 1 (Scaled dot-product attention) Scaled dot-product attention takes \(m\) queries, the rows of an \(m \times d_k\) matrix \(\matr{Q}\), and \(n\) keys and \(n\) values, the rows of an \(n \times d_k\) matrix \(\matr{K}\) and an \(n \times d_v\) matrix \(\matr{V}\). It returns the \(m \times d_v\) matrix

\[ \operatorname{Attention}\paren{\matr{Q}, \matr{K}, \matr{V}} \eqdef \operatorname{softmax}\paren{\frac{\matr{Q} \tp{\matr{K}}}{\sqrt{d_k}}} \matr{V}, \]

with the softmax taken across each row [2, Sec. 3.2.1]. Row \(i\) of the softmax holds weights \(\attnweight_{i1}, \dots, \attnweight_{in}\), which are positive and sum to 1, so row \(i\) of the output is a weighted average of the rows of \(\matr{V}\). Bahdanau et al. [3] scored each key with a small network instead of a dot product. Vaswani et al. [2, Sec. 3.2.1] call that form additive attention.

ExmExample 1 (Attention in PyTorch)

Example 1 (Attention in PyTorch)  

Show code
torch_output = F.scaled_dot_product_attention(
    q.reshape(1, 2), keys, values.reshape(3, 1)
)
by_hand = torch.softmax(keys @ q / math.sqrt(2), dim=0) @ values
print(torch_output, by_hand)
tensor([[17.0802]]) tensor(17.0802)

The query and keys of Exercise 1 have \(d_k = 2\), so scaled dot-product attention divides the scores by \(\sqrt{2}\) before the softmax. F.scaled_dot_product_attention [4] returns 17.08, the same as the formula computed by hand. The scaled scores are closer together, so the average is nearer the plain mean of the values, 20, than the unscaled average of Solution 1, 15.79.

2.2 Scaling the scores

ExrExercise 2 (Why divide by \(\sqrt{d_k}\)?)

Exercise 2 (Why divide by \(\sqrt{d_k}\)?) Draw a query \(\vq\) and a key \(\vecf{k}\) in \(\reals^{d_k}\) with independent standard normal entries. How does the variance of \(\dprod{\vq}{\vecf{k}}\) depend on \(d_k\)?

SolutionSolution 2

Solution 2. Since \(q_j\) and \(k_j\) are independent, each term \(q_j k_j\) has mean \(\E{q_j k_j} = \E{q_j} \E{k_j} = 0\). Its variance is

\[ \begin{aligned} \Var{q_j k_j} &= \E{q_j^2 k_j^2} - \paren{\E{q_j k_j}}^2 \\ &= \E{q_j^2} \E{k_j^2} - 0 && \text{(independence)} \\ &= 1 \cdot 1 && \text{(mean 0 and variance 1)} \\ &= 1. \end{aligned} \]

The \(d_k\) terms are independent, so their variances add:

\[ \begin{aligned} \Var{\dprod{\vq}{\vecf{k}}} &= \Var{\sumto{j}{d_k} q_j k_j} \\ &= \sumto{j}{d_k} \Var{q_j k_j} && \text{(independent terms)} \\ &= d_k. && \text{(each variance is 1)} \end{aligned} \]

Vaswani et al. [2, Sec. 3.2.1], footnote 4 give the same argument.

Show code
generator = torch.Generator().manual_seed(0)
dims = [4, 64, 1024]
dot_vars = []
for d in dims:
    q_draws = torch.randn(10_000, d, generator=generator)
    k_draws = torch.randn(10_000, d, generator=generator)
    dot_vars.append((q_draws * k_draws).sum(dim=1).var().item())
print(dot_vars)
[3.969802141189575, 64.14726257324219, 1031.2110595703125]

The variance grows in proportion to \(d_k\). From 10,000 draws, the sample variances for \(d_k = 4\), 64 and 1024 are 4.0, 64.1 and 1031. Dividing a quantity by a constant \(c\) divides its variance by \(c^2\), so dividing the dot product by \(\sqrt{d_k}\) gives variance \(d_k / d_k = 1\), whatever \(d_k\) is.

RemarkRemark 1 (What the scaling prevents)

Remark 1 (What the scaling prevents).

Show code
d_k, n_keys = 512, 64
q_draws = torch.randn(1_000, 1, d_k, generator=generator)
k_draws = torch.randn(1_000, n_keys, d_k, generator=generator)
raw_scores = (q_draws @ k_draws.transpose(1, 2)).squeeze(1)
top_raw = torch.softmax(raw_scores, dim=1).max(dim=1).values.mean().item()
top_scaled = torch.softmax(raw_scores / math.sqrt(d_k), dim=1).max(dim=1).values.mean().item()
print(top_raw, top_scaled)
0.9229199290275574 0.10691015422344208

With \(d_k = 512\) and 64 keys drawn as in Exercise 2, the unscaled softmax gives its largest weight an average of 0.92, so each query mostly copies one value. After dividing by \(\sqrt{d_k}\), the largest weight averages 0.11. Vaswani et al. [2, Sec. 3.2.1] suggest why the scaling helps: where one weight is near 1, the softmax’s gradient is near 0, and training slows.

2.3 Attending to another sequence

ExrExercise 3 (Where should a translator look?)

Exercise 3 (Where should a translator look?) A recurrent network reads a French sentence and keeps a hidden state for each French word. A second recurrent network then writes the English sentence one word at a time. Which of the French hidden states should the second network use when it writes each English word?

SolutionSolution 3

Solution 3. All of them, weighted by how relevant each French word is to the English word being written. Earlier translation networks passed only the last French hidden state to the second network, so one vector had to hold the whole sentence. Bahdanau et al. [3, Sec. 3.1] let the second network compute weights over every French hidden state at each step instead, and translation of long sentences improved [3, Sec. 5.1].

DefDefinition 2 (Cross-attention (encoder-decoder attention))

Definition 2 (Cross-attention (encoder-decoder attention)) Cross-attention is scaled dot-product attention whose queries are computed from one sequence, and whose keys and values are computed from another. Vaswani et al. [2, Sec. 3.2.3] call it encoder-decoder attention, since its queries come from the network that writes the output and its keys and values from the network that read the input.

Show code

nn.MultiheadAttention [5] takes the queries’ sequence first, then the keys’ and the values’. Here the queries come from a sequence of 3 vectors and the keys and values from a different sequence of 5, so the cross-attention output has one row for each of the 3 queries, and the weights form a \(3 \times 5\) matrix whose rows each sum to 1.

3 Within one sequence

3.1 One step from any position

ExrExercise 4 (How far does information travel?)

Exercise 4 (How far does information travel?) A GRU language model reads 64 characters. How many times does it apply its recurrent update between reading the first character and predicting the character after the 64th?

SolutionSolution 4

Solution 4. 63 times, once for each of characters 2 to 64. Whatever the network keeps about the first character has to survive all 63 updates, and the gradient of the loss with respect to that character has to pass back through all of them in training, where it can vanish. Attention can connect the last position to the first in one step, if the queries come from the same sequence as the keys.

DefDefinition 3 (Self-attention)

Definition 3 (Self-attention) Self-attention is scaled dot-product attention whose queries, keys and values all come from the same sequence. For a sequence of \(n\) vectors in \(\reals^d\), the rows of an \(n \times d\) matrix \(\matr{X}\), it computes

\[ \matr{Q} = \matr{X} \matr{W}_Q, \qquad \matr{K} = \matr{X} \matr{W}_K, \qquad \matr{V} = \matr{X} \matr{W}_V, \]

and returns \(\operatorname{Attention}\paren{\matr{Q}, \matr{K}, \matr{V}}\), where the matrices \(\matr{W}_Q\), \(\matr{W}_K\) and \(\matr{W}_V\), of size \(d \times d_k\), \(d \times d_k\) and \(d \times d_v\), are parameters learned in training [2, Sec. 3.2.3]. Each position’s output is a weighted average over every position of the sequence, itself included.

ExmExample 3 (Self-attention over “First Citizen”)

Example 3 (Self-attention over “First Citizen”)

Show code

torch.Size([1, 13, 8]) torch.Size([1, 13, 13])

The first line of the text begins with the 13 characters "First Citizen". An embedding layer turns each into a vector of 8 numbers, and passing the same tensor as queries, keys and values makes nn.MultiheadAttention compute self-attention, followed by a linear layer. The weights form a \(13 \times 13\) matrix: one row of weights over all 13 characters for each character.

3.2 Order

ExrExercise 5 (Reading backwards)

Exercise 5 (Reading backwards) Feed the 13 characters of Example 3 to the same self-attention layer in reverse order. How do its outputs change?

SolutionSolution 5

Solution 5.

Show code
with torch.no_grad():
    x_reversed = embed(line.flip(1))
    reversed_out, _ = attend(x_reversed, x_reversed, x_reversed)
reverse_gap = (reversed_out - self_out.flip(1)).abs().max().item()
print(reverse_gap)
5.960464477539063e-08

The outputs come out in reverse order and are otherwise unchanged: the largest difference between the new outputs and the old ones reversed is 6e-08, a rounding error. Each character’s output is a weighted average whose weights depend on the vectors and not on where they sit, so self-attention on its own cannot tell "First Citizen" from "nezitiC tsriF".

DefDefinition 4 (Permutation equivariance)

Definition 4 (Permutation equivariance) A function \(f\) from sequences of vectors to sequences of vectors of the same length is permutation equivariant when reordering its input reorders its output the same way: \(f(\pi(\matr{X})) = \pi(f(\matr{X}))\) for every sequence \(\matr{X}\) and every reordering \(\pi\) of its positions [6, Sec. 2]. Self-attention is permutation equivariant, as Solution 5 found for one reordering.

ExmExample 4 (A GRU is not permutation equivariant)

Example 4 (A GRU is not permutation equivariant)  

Show code
_ = torch.manual_seed(0)
gru = nn.GRU(8, 8, batch_first=True)
with torch.no_grad():
    gru_out, _ = gru(x)
    gru_reversed, _ = gru(x_reversed)
gru_gap = (gru_reversed - gru_out.flip(1)).abs().max().item()
print(gru_gap)
0.5011376142501831

A GRU layer given the same 13 vectors forwards and backwards does not just reverse its outputs: the largest difference between the two is 0.50, against 6e-08 for self-attention in Solution 5. Each hidden state depends on the vectors before it, so the GRU is not permutation equivariant.

3.3 Positions

ExrExercise 6 (Telling positions apart)

Exercise 6 (Telling positions apart) How could we change the input vectors of Example 3 so that the same character at two different positions gets two different vectors?

SolutionSolution 6

Solution 6. Add to each character’s vector a second vector that depends only on the character’s position. The letter i at positions 2, 8 and 10 of "First Citizen" then enters the layer as three different vectors, and reordering the characters changes the inputs as well as their order.

DefDefinition 5 (Positional encoding)

Definition 5 (Positional encoding) A positional encoding is a vector \(\vp_t \in \reals^d\) added to the embedding of the symbol at position \(t\), before the first self-attention layer. Vaswani et al. [2, Sec. 3.5] fix \(\vp_t\) as sines and cosines of \(t\) at different frequencies; Radford et al. [7, Sec. 4.1] learn \(\vp_t\) instead, as row \(t\) of a second embedding matrix. These notes learn them.

ExmExample 5 (Order matters once positions are added)

Example 5 (Order matters once positions are added)  

Show code
_ = torch.manual_seed(0)
position = nn.Embedding(13, 8)
where = torch.arange(13)
with torch.no_grad():
    x_pos = embed(line) + position(where)
    x_pos_reversed = embed(line.flip(1)) + position(where)
    pos_out, _ = attend(x_pos, x_pos, x_pos)
    pos_reversed, _ = attend(x_pos_reversed, x_pos_reversed, x_pos_reversed)
pos_gap = (pos_reversed - pos_out.flip(1)).abs().max().item()
print(pos_gap)
0.8557268381118774

With a learnable (here untrained) positional encoding added to each character’s vector, the outputs for the reversed line are no longer the old outputs reversed: the largest difference is 0.86, against 6e-08 without it.

3.4 Not looking ahead

ExrExercise 7 (Peeking at the answer)

Exercise 7 (Peeking at the answer) A language model trained with teacher forcing predicts the next character at every position of a window at once. Suppose its self-attention lets position \(t\) attend to position \(t + 1\). What stops the model from reaching a training loss near 0?

SolutionSolution 7

Solution 7. Nothing stops it. The character it must predict at position \(t\) is the input at position \(t + 1\), so the model can learn to copy it. That model is useless for generating text, where the next character does not exist yet. The weights on every key after the query have to be 0.

DefDefinition 6 (Causal mask)

Definition 6 (Causal mask) A causal mask sets the score of key \(j\) for query \(i\) to \(-\infty\) whenever \(j > i\), before the softmax in self-attention. The softmax then gives those keys weight 0, so each position attends only to itself and the positions before it [2, Sec. 3.2.3].

4 Stacking

4.1 Several heads

ExrExercise 8 (Two things to look at)

Exercise 8 (Two things to look at) A self-attention layer gives each query one row of weights over the positions. Can that one row put more than 0.9 of its weight on the previous character and also more than 0.9 on the first character of the current word?

SolutionSolution 8

Solution 8. No, unless the two are the same position. The weights in a row are positive and sum to 1, so 0.9 on one position leaves at most 0.1 for every other position. Looking at both needs two rows of weights for each query, each computed from its own query and key matrices.

DefDefinition 7 (Multi-head attention)

Definition 7 (Multi-head attention) Multi-head attention with \(h\) heads runs \(h\) copies of scaled dot-product attention side by side, head \(i\) with its own matrices \(\matr{W}_Q^{(i)}\), \(\matr{W}_K^{(i)}\) and \(\matr{W}_V^{(i)}\) of size \(d \times d / h\). It joins the \(h\) outputs, each \(n \times d / h\), into one \(n \times d\) matrix, and multiplies that by a \(d \times d\) matrix \(\matr{W}_O\) of parameters [2, Sec. 3.2.2]. Each head can weight the positions in its own way.

ExmExample 7 (Counting the parameters)

Example 7 (Counting the parameters)

nn.MultiheadAttention(64, 4) is multi-head attention with \(d = 64\) and 4 heads. It stores the three projections of all heads in one \(192 \times 64\) matrix with 192 biases, and \(\matr{W}_O\) as a \(64 \times 64\) linear layer with 64 biases. That is \(3 \times 64^2 + 192 + 64^2 + 64 = 16,640\) parameters.

ExrExercise 9 (Do more heads cost more?)

Exercise 9 (Do more heads cost more?) Does nn.MultiheadAttention(64, num_heads) have more parameters with 16 heads than with 1?

SolutionSolution 9

Solution 9.

4.2 The block

ExrExercise 10 (Mixing, then transforming)

Exercise 10 (Mixing, then transforming) Self-attention applies no nonlinear function to each position’s vector on its own. Which layer from the feedforward networks chapter could then apply a nonlinear function to each position’s vector?

SolutionSolution 10

Solution 10. An MLP, applied to each position’s vector separately, with the same weights at every position. The self-attention mixes information across positions, and the MLP transforms each position’s vector on its own.

DefDefinition 8 (Transformer block)

Definition 8 (Transformer block) A Transformer block maps an \(n \times d\) matrix \(\matr{H}\) to another \(n \times d\) matrix in two steps, each wrapped in a residual connection:

\[ \begin{aligned} \matr{H}' &= \matr{H} + \operatorname{MultiHead}\paren{\operatorname{LN}\paren{\matr{H}}}, \\ \operatorname{Block}\paren{\matr{H}} &= \matr{H}' + \operatorname{MLP}\paren{\operatorname{LN}\paren{\matr{H}'}}, \end{aligned} \]

where \(\operatorname{MultiHead}\) is multi-head attention, \(\operatorname{LN}\) is layer normalization of each row, and \(\operatorname{MLP}\) is an MLP with one hidden layer, applied to each row. Vaswani et al. [2, Secs. 3.1, 3.3] build each step this way, but normalize after each sum instead of before each step. The order here is the Pre-LN Transformer of Xiong et al. [8, Sec. 3], which they find trains without a warm-up of the learning rate.

Its 49,984 parameters are 16,640 in the attention, 33,088 in the MLP and 256 in the two layer normalization layers. A sequence of 10 vectors of 64 numbers comes out as 10 vectors of 64 numbers.

5 A Transformer language model

5.1 The networks

Show code
seq_len = 64
batch_size = 32


class CharTransformer(nn.Module):
    # Embeds each character and its position, applies `n_blocks` causal
    # Transformer blocks, and returns logits over the next character.

    def __init__(self, d_model=64, n_heads=4, n_blocks=2):
        super().__init__()
        self.embed = nn.Embedding(n_chars, d_model)
        self.position = nn.Embedding(seq_len, d_model)
        self.blocks = nn.ModuleList([
            nn.TransformerEncoderLayer(
                d_model, n_heads, dim_feedforward=4 * d_model,
                dropout=0.0, batch_first=True, norm_first=True,
            )
            for _ in range(n_blocks)
        ])
        self.norm = nn.LayerNorm(d_model)
        self.out = nn.Linear(d_model, n_chars)

    def forward(self, x):
        n = x.shape[1]
        h = self.embed(x) + self.position(torch.arange(n))
        mask = nn.Transformer.generate_square_subsequent_mask(n)
        for block in self.blocks:
            h = block(h, src_mask=mask, is_causal=True)
        return self.out(self.norm(h))


class CharGRU(nn.Module):
    # The GRU language model of the language models chapter.

    def __init__(self, embed_size=16, hidden_size=128):
        super().__init__()
        self.embed = nn.Embedding(n_chars, embed_size)
        self.recurrent = nn.GRU(embed_size, hidden_size, batch_first=True)
        self.out = nn.Linear(hidden_size, n_chars)

    def forward(self, x):
        states, _ = self.recurrent(self.embed(x))
        return self.out(states)


def train_lm(net, n_steps, lr, seed=0):
    # Adam on random windows of the training text, with gradient clipping to 1.
    # Each window's targets are the same window moved one character on.
    optimizer = torch.optim.Adam(net.parameters(), lr=lr)
    generator = torch.Generator().manual_seed(seed)
    net.train()
    for step in range(n_steps):
        starts = torch.randint(0, n_train - seq_len - 1, (batch_size,), generator=generator)
        x = torch.stack([train_ids[s:s + seq_len] for s in starts])
        y = torch.stack([train_ids[s + 1:s + seq_len + 1] for s in starts])
        loss = F.cross_entropy(net(x).reshape(-1, n_chars), y.reshape(-1))
        optimizer.zero_grad()
        loss.backward()
        _ = nn.utils.clip_grad_norm_(net.parameters(), 1)
        optimizer.step()


def val_perplexity(net):
    # Perplexity on the validation text, read in windows of `seq_len` characters.
    n = (len(val_ids) - 1) // seq_len * seq_len
    x = val_ids[:n].reshape(-1, seq_len)
    y = val_ids[1:n + 1].reshape(-1, seq_len)
    net.eval()
    with torch.no_grad():
        loss = F.cross_entropy(net(x).reshape(-1, n_chars), y.reshape(-1))
    return math.exp(loss.item())


_ = torch.manual_seed(1)
transformer = CharTransformer()
_ = torch.manual_seed(1)
gru_lm = CharGRU()
print(n_params(transformer), n_params(gru_lm))
112061 64909

CharTransformer adds a learned positional encoding to each character’s embedding, applies two Transformer blocks with 4 heads and a causal mask, and maps each position’s vector to logits over the next character. CharGRU is the GRU model of the language models chapter. The two have 112,061 and 64,909 parameters. train_lm() runs Adam on batches of 32 windows of 64 characters, with gradient clipping to 1. val_perplexity() reads the validation text in windows of 64 characters, the longest the positional encoding covers, and returns the perplexity.

6 Targets from text

6.1 Two objectives

ExrExercise 13 (Who labelled the text?)

Exercise 13 (Who labelled the text?) Nobody labelled the Shakespeare text. Where did the targets in train_lm() come from?

SolutionSolution 13

Solution 13. From the text itself. Each window’s targets are the same window moved one character on, so any text at all gives as many targets as it has characters.

DefDefinition 9 (Pretraining)

Definition 9 (Pretraining) Pretraining trains a network on unlabelled data, using targets that come from the data itself. Radford et al. [7, Sec. 3.1] pretrain a Transformer with a causal mask to predict each next token. Devlin et al. [10, Sec. 3.1] pretrain one without a causal mask to predict tokens hidden from its input, choosing 15% of the positions at random. Both then fine-tune the pretrained network on tasks with labels.

Hiding each character with probability 0.15 turns the first line of the text into the input “First C_t_zen:”. A network pretrained in the second way learns to fill each gap from the characters on both sides of it. The train_lm() of this lecture uses the objective of the first way, on 90,000 characters rather than the billions of tokens of real language models.
