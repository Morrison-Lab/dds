1 Welcome

1.1 Plan for this lecture

The recurrent networks chapter read whole sequences and classified them, and ended by turning symbols into vectors with an embedding layer. This lecture predicts text one character at a time:

  1. the probability of a string, built from the probability of each next character;
  2. a model that counts pairs of characters;
  3. a number that scores how well a model predicts held-out text;
  4. a recurrent network that predicts each next character;
  5. drawing new text from that network.

2 Counting

2.1 The probability of a string

Exercise 1 (The probability of a word)

Exercise 1 (The probability of a word) Let \(X_1, X_2, X_3\) be the next three characters of a text. Use the chain rule of probability to write \(\Prf{X_1 = \texttt{t}, X_2 = \texttt{h}, X_3 = \texttt{e}}\) as a product of three probabilities, each about one character.

Solution 1

Solution 1. The chain rule of probability conditions each character on the ones before it:

\[\begin{aligned} &\Prf{X_1 = \texttt{t}, X_2 = \texttt{h}, X_3 = \texttt{e}} \\ &\quad = \Prf{X_1 = \texttt{t}} \condPr{X_2 = \texttt{h}}{X_1 = \texttt{t}} \condPr{X_3 = \texttt{e}}{X_1 = \texttt{t}, X_2 = \texttt{h}}. \end{aligned}\]

Each factor is the probability of one character given the characters before it. A model that gives these conditional probabilities for every string of earlier characters gives the probability of every string.

Definition 1 (Language model)

Definition 1 (Language model) A language model gives, for each position \(t\) in a sequence of symbols \(x_1, \dots, x_n\), a probability distribution \(\condPr{X_t = x}{x_1, \dots, x_{t-1}}\) over the symbol \(x\) at that position, given the symbols before it [2, Sec. 12.4]. By the chain rule of probability, the product of these probabilities over \(t = 1, \dots, n\) is the probability of the whole sequence. The symbols, often called tokens, can be characters or words; these notes use characters.

Example 1 (A uniform language model)

Example 1 (A uniform language model)  

Show code
uniform_the = (1 / n_chars) ** 3
print(uniform_the)
4.40565509888493e-06

The simplest language model for this text gives each of the 61 characters probability \(1 / 61\) at every position, whatever came before. It gives "the" probability \((1 / 61)^3\), or 1 in 226,981, the same as any other string of three characters, such as "qzx".

Definition 2 (Bigram model)

Definition 2 (Bigram model) A bigram model is a language model in which the distribution of each symbol depends only on the symbol before it [2, Sec. 12.4.1]. Counting in a training text estimates it as

\[ \hPr{}\paren{X_t = b \given X_{t-1} = a} = \frac{N(a, b)}{N(a)}, \]

where \(N(a, b)\) counts how often \(a\) is followed by \(b\), and \(N(a)\) counts how often \(a\) is followed by any symbol [3, Sec. 3.1.2]. An \(n\)-gram model conditions on the \(n - 1\) symbols before each one in the same way.

Example 2 (A bigram model of the training text)

Example 2 (A bigram model of the training text)

pair_counts = torch.zeros(n_chars, n_chars)
_ = pair_counts.index_put_(

row_totals = pair_counts.sum(dim=1, keepdim=True)
counted = pair_counts / row_totals
after_t = counted[index["t"]]

p_top_after_t = after_t.max().item()
p_u_after_q = counted[index["q"], index["u"]].item()

'h' 0.33165013790130615 1.0

Row \(a\) of pair_counts holds \(N(a, b)\) for every \(b\). So row \(a\) of counted is the bigram model’s distribution of the character after \(a\). Its most likely character after t is h, with probability 0.33. It gives a u after a q probability 1.00, the share found in Solution 2.

Exercise 3 (Pairs the training text never shows)

Solution 3

Solution 3.

12

At 12 of the 9,999 positions after the first, the pair of characters never occurs in the training text. The counting estimate of Example 2 gives each of those 12 pairs probability 0, and so the whole validation text probability 0.

Definition 3 (Add-one smoothing (Laplace smoothing))

Definition 3 (Add-one smoothing (Laplace smoothing)) Add-one smoothing (also called Laplace smoothing) adds 1 to every count before estimating a bigram model. With \(K\) possible symbols, the estimate becomes

\[ \hPr{}\paren{X_t = b \given X_{t-1} = a} = \frac{N(a, b) + 1}{N(a) + K}, \]

so every pair gets a probability above 0, including pairs the training text never shows [3, Sec. 3.6.1].

Example 3 (The smoothed bigram model)

Example 3 (The smoothed bigram model)  

Show code
bigram = (pair_counts + 1) / (row_totals + n_chars)
p_u_after_q_smoothed = bigram[index["q"], index["u"]].item()
p_unseen_min = bigram[~seen].min().item()
print(p_u_after_q_smoothed, p_unseen_min)
0.35483869910240173 7.509198621846735e-05

With add-one smoothing, the bigram model gives a u after a q probability 0.35 rather than 1.00. There are only 32 qs to count, so the 61 added ones are a large part of the row. The pairs the training text never shows now get probabilities of at least 1 in 13,317.

3 Scoring a language model

3.1 Average log probability

Exercise 4 (Scoring held-out text)

Exercise 4 (Scoring held-out text) For each validation character after the first, take the natural log of the probability the smoothed bigram model of Example 3 gives it, given the character before it. What is the average of the negatives of these logs?

Solution 4

Solution 4.

Show code

uniform_nll = math.log(n_chars)

2.3827016353607178 4.110873864173311
Show code
# The prose below says the bigram model's average is the lower one.
assert bigram_nll < uniform_nll

The average is 2.38. The uniform model of Example 1 gives every character probability \(1 / 61\), so its average is \(\log 61 = 4.11\). The lower average means the bigram model gives the validation text higher probability. This average is the cross-entropy loss of the model’s predictions of the validation characters.

Definition 4 (Perplexity)

Definition 4 (Perplexity) The perplexity of a language model on a sequence \(x_1, \dots, x_n\) is

\[ \expf{-\avgtof{t}{n}{\logf{\condPr{X_t = x_t}{x_1, \dots, x_{t-1}}}}}, \]

the exponential of the average negative log probability per symbol [3, Sec. 3.3]. It equals the probability of the whole sequence raised to the power \(-1/n\), and it is the same number when the logs are base 2 and the exponential is \(2^{(\cdot)}\). The DATA 471 notes define it for any classifier in the same way, and find that a model which gives probability \(1/K\) to each of \(K\) symbols has perplexity \(K\). Lower is better.

Example 4 (Perplexity of the two counting models)

Example 4 (Perplexity of the two counting models)

4 A recurrent language model

4.1 The network

Show code
seq_len = 64
batch_size = 32
lm_lr = 0.005


class CharModel(nn.Module):
    # Embeds each character, reads the sequence with a GRU,
    # and returns logits over the next character at every position.

    def __init__(self, embed_size=16, hidden_size=128):
        super().__init__()
        self.embed = nn.Embedding(n_chars, embed_size)
        self.recurrent = nn.GRU(embed_size, hidden_size, batch_first=True)
        self.out = nn.Linear(hidden_size, n_chars)

    def forward(self, x, state=None):
        states, state = self.recurrent(self.embed(x), state)
        return self.out(states), state


def make_lm(seed=1):
    torch.manual_seed(seed)
    return CharModel()


def train_lm(net, n_steps, seed=0):
    # Adam on random windows of the training text, with gradient clipping to 1.
    # Each window's targets are the same window moved one character on.
    optimizer = torch.optim.Adam(net.parameters(), lr=lm_lr)
    generator = torch.Generator().manual_seed(seed)
    net.train()
    for step in range(n_steps):
        starts = torch.randint(0, n_train - seq_len - 1, (batch_size,), generator=generator)
        x = torch.stack([train_ids[s:s + seq_len] for s in starts])
        y = torch.stack([train_ids[s + 1:s + seq_len + 1] for s in starts])
        logits, _ = net(x)
        loss = nn.functional.cross_entropy(logits.reshape(-1, n_chars), y.reshape(-1))
        optimizer.zero_grad()
        loss.backward()
        _ = nn.utils.clip_grad_norm_(net.parameters(), 1)
        optimizer.step()


def lm_log_probs(net):
    # Natural log of the probability `net` gives each validation character
    # after the first, given all the validation characters before it.
    net.eval()
    with torch.no_grad():
        logits, _ = net(val_ids[:-1].unsqueeze(0))
    log_p = torch.log_softmax(logits[0], dim=1)
    return log_p[torch.arange(len(val_ids) - 1), val_ids[1:]]


print(make_lm())
CharModel(
  (embed): Embedding(61, 16)
  (recurrent): GRU(16, 128, batch_first=True)
  (out): Linear(in_features=128, out_features=61, bias=True)
)

CharModel reads a sequence of character indices with an embedding layer and a GRU layer, and maps the hidden state at each position to logits over the next character. train_lm() runs Adam with learning rate 0.005 on batches of 32 windows of 64 characters, with gradient clipping to 1. lm_log_probs() returns the log of the probability the network gives each validation character, given the validation characters before it.

Definition 5 (Teacher forcing)

Definition 5 (Teacher forcing) Teacher forcing trains a recurrent language model on a text by feeding it the true text as input, and asking it at each position for the next symbol of the same text [2, Sec. 10.2.1]. The targets are the inputs moved one position on. The model never reads its own predictions during training.

5 Generating text

5.1 Sampling

Exercise 7 (Writing new lines)

Exercise 7 (Writing new lines) Draw 1,000 characters from the trained network of Solution 5 with sample(lm, "MENENIUS:\n", 1000). What share of the drawn words occur somewhere in the training text?

Show code
def sample(net, prompt, n, temperature=1.0, seed=0):
    # Feeds `prompt`, then draws `n` characters one at a time,
    # feeding each one back in.
    generator = torch.Generator().manual_seed(seed)
    x = torch.tensor([[index[ch] for ch in prompt]])
    drawn = []
    net.eval()
    with torch.no_grad():
        logits, state = net(x)
        for _ in range(n):
            p = torch.softmax(logits[0, -1] / temperature, dim=0)
            nxt = torch.multinomial(p, 1, generator=generator)
            drawn.append(nxt.item())
            logits, state = net(nxt.view(1, 1), state)
    return prompt + decode(torch.tensor(drawn))


print(sample(make_lm(), "MENENIUS:\n", 40))
MENENIUS:

sample() draws each character from the network’s distribution over the next character, given the prompt and the characters drawn so far; the untrained network above draws characters close to at random.

def real_word_share(s):

    words = re.findall(r"[a-z]+", s[len(prompt):].lower())

Exercise 8 (Dividing the logits)

Dividing by 0.5 gives the first symbol probability 0.87, against 0.67 for \(\vz\) itself and 0.51 for \(\vz / 2\). Dividing by a number below 1 spreads the logits apart, which moves probability to the largest; dividing by a number above 1 brings them together, which moves the probabilities toward \(1/3\) each.

Definition 6 (Temperature)

Definition 6 (Temperature) Sampling at temperature \(T > 0\) draws the next symbol from the softmax of \(\vz / T\), where \(\vz\) is the vector of the model’s logits. Hinton et al. [5, Sec. 2] use this softmax with temperature \(T\), and note that a higher \(T\) gives a softer distribution. At \(T = 1\) sampling uses the model’s own distribution. As \(T\) falls toward 0, the distribution puts more of its weight on the most likely symbols, and as \(T\) grows, the distribution approaches the uniform distribution.
